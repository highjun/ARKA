# 무엇을 가져올까 — VSCode·OpenClaw 기능 체크리스트

두 오픈소스가 **이미 답을 낸 자리**를 의미 단위로 편 목록이다. 폴더 이름이 아니라 "무슨 일을 하는가"로 묶었다.
갯수는 기능의 양이 아니다 — VSCode 확장 97개 중 절반이 언어 문법이고, OpenClaw 확장 165개 중 절반이 모델 제공자다.

읽은 지점: VSCode `dbf2175d`, OpenClaw `9894068e` (2026-09-14).

줄마다 넷을 적었다 — **무슨 일인가**, VSCode는 어떻게 하나, OpenClaw는 어떻게 하나, **ARKA는 지금 어떤가**.
판정은 체크박스에 표시하고 사유를 한 줄 덧붙인다. 어휘는 다섯이다.

- **가져온다** — 모양까지 본뜬다
- **개념만** — 생각만 빌리고 모양은 우리 것으로
- **이미 있다** — 자리가 있다. 모양이 맞는지는 따로 본다
- **안 가져온다** — 사유가 "우리 전제에 그 시나리오가 없다"여야 한다
- **나중에** — 시나리오는 있으나 지금 아니다. 무엇이 먼저인지 적는다

ARKA의 전제는 이렇다 — 단일 사용자, 사용자 PC 한 대, 터널 뒤라 앱이 인증을 모름, 설치형 PWA,
데스크톱·모바일 기능 동등. "안 가져온다"의 사유는 대개 이 다섯 중 하나에서 나온다.

판정이 끝나면 **결정은 `docs/adr/`로, 남는 일은 새 태스크로** 나가고 이 파일은 Done으로 닫는다.

## 껍데기

- [ ] **화면 배치** — 활동 막대·사이드바·편집 영역·분할을 나누고 크기를 기억한다.
  - VSCode: 파트(part)마다 자기 자리를 갖고 레이아웃 서비스가 조립한다
  - OpenClaw: 없다. 웹 채팅 UI 하나다
  - ARKA: `ITabsModel`이 leaf/split 트리를 들고 `Shell`이 그린다
- [ ] **명령** — 기능 하나를 id로 부르는 체계. 팔레트·메뉴·키바인딩이 전부 이 id를 가리킨다.
  - VSCode: `ICommandService.executeCommand(id, ...args)`가 중심
  - OpenClaw: `registerCommand`. 슬래시 명령으로도 노출된다
  - ARKA: 등록은 있는데 **id로 부르는 길이 없다**. 부르는 쪽이 레지스트리에서 꺼내 직접 실행한다
- [ ] **조건** — "지금 이 상황일 때만"을 표현한다.
  - VSCode: `when` 문자열을 파서가 식으로 바꾼다. 갈래가 열넷
  - OpenClaw: 없다. 설정 값으로 켜고 끈다
  - ARKA: `when`이 **함수**다. 그래서 선언에 실을 수 없고 설정으로 바꿀 수도 없다
- [ ] **단축키** — 키를 커맨드에 잇는다.
  - VSCode: 기기별(`mac`·`linux`·`win`)로 갈리고 두 벌 키(화음)를 받는다
  - OpenClaw: 없다
  - ARKA: 문자열 하나. 기기 구분이 없는데 **데스크톱·모바일이 전제**다
- [ ] **메뉴** — 항목을 자리와 묶음과 순서로 배치한다.
  - VSCode: `MenuId`가 닫힌 집합이고 `group`·`order`로 정렬
  - OpenClaw: 없다
  - ARKA: `group`·`order`는 같고 `menuId`가 열린 문자열이라 오타가 조용히 빈 메뉴가 된다
- [ ] **빠른 실행** — 무엇이든 검색해 실행하는 한 칸.
  - VSCode: 팔레트와 `Ctrl+P`가 같은 장치의 두 모드
  - OpenClaw: 슬래시 명령
  - ARKA: `CommandPalette`가 있다. 파일 열기 모드는 없다
- [ ] **알림** — 일어난 일을 알린다.
  - VSCode: 심각도·**동작 버튼**·진행률·"다시 보지 않기"
  - OpenClaw: 채널로 메시지를 보낸다
  - ARKA: 심각도와 글만. **버튼이 없어서** 업데이트 안내가 알림 밖 배너로 따로 산다
- [ ] **설정** — 사용자가 바꾸는 값.
  - VSCode: 확장이 스키마로 항목을 더하고, 값의 층이 넷(기본·사용자·워크스페이스·언어별)
  - OpenClaw: 파일 하나에 모든 플러그인 설정. 플러그인이 JSON Schema를 낸다
  - ARKA: 고정 두 항목. **확장이 설정을 더할 수 없다**
- [ ] **상태 보존** — 껐다 켜도 남는 값.
  - VSCode: 스코프가 셋이고 확장마다 자기 저장소를 받는다
  - OpenClaw: 플러그인별 상태 폴더
  - ARKA: `IStorage` 키 공간이 하나. 확장이 쓰면 **키가 부딪힌다**
- [ ] **테마·색** — 화면의 색을 한 자리에서 정한다.
  - VSCode: 색 토큰을 확장이 기여한다. 내장 테마가 12개
  - OpenClaw: 없다
  - ARKA: Primer 토큰으로 고정하고 라이트·다크 둘 (→ ADR 0009)
- [ ] **접근성** — 스크린리더·키보드만으로 쓰기·소리 신호.
  - VSCode: 전용 기여 둘과 뷰마다 도움말
  - OpenClaw: 해당 없음
  - ARKA: `axe`가 스토리를 검사한다. 도움말·소리 신호는 없다
- [ ] **현지화** — 화면 글자를 언어별로.
  - VSCode: 언어팩 확장과 `l10n` 번들
  - OpenClaw: 없다
  - ARKA: 한국어 고정
- [ ] **온보딩·안내** — 처음 쓰는 사람에게 무엇을 하라고 알려 준다.
  - VSCode: 둘러보기·빈 뷰 안내·배너·설문까지 여섯 갈래
  - OpenClaw: 설치 마법사
  - ARKA: 없다. 만드는 사람과 쓰는 사람이 같다
- [ ] **업데이트** — 새 판이 나온 것을 알리고 적용한다.
  - VSCode: 백그라운드 내려받기와 재시작 안내
  - OpenClaw: CLI로 갱신
  - ARKA: 프로토콜 버전이 어긋나면 배너로 새로고침을 권한다

## 확장 체계

- [ ] **기여 선언** — 확장이 무엇을 더하는지 데이터로 적는다.
  - VSCode: `package.json`의 `contributes`. 확장을 켜기 전에 읽는다
  - OpenClaw: `openclaw.plugin.json`. 필드 주석이 "런타임 로드 전에 읽는 싼 메타데이터"라고 적는다
  - ARKA: 없다. 조립부 코드를 읽어야 무엇을 기여하는지 안다
- [ ] **기여 지점** — 어디에 꽂을 수 있는가의 목록.
  - VSCode: 확장이 **새 지점을 만들 수 있다**(`registerExtensionPoint` + JSON Schema)
  - OpenClaw: `api.register*` 메서드 일흔 남짓
  - ARKA: 레지스트리 다섯(커맨드·활동·패널·탭·시작). 닫혀 있다
- [ ] **활성화** — 언제 확장을 켜나.
  - VSCode: `activationEvents`로 늦게 켠다(`onCommand:`·`onLanguage:`·`workspaceContains:`)
  - OpenClaw: `activation.onStartup`·`onCommands`·`onChannels` 등으로 계획을 세운다
  - ARKA: 전부 셸이 뜰 때 켜진다. 번들에 정적으로 들어 있다
- [ ] **확장 격리** — 확장이 본체를 망가뜨리지 못하게 한다.
  - VSCode: 확장 호스트가 별도 프로세스. 웹뷰는 샌드박스된 iframe
  - OpenClaw: 신뢰 등급을 매니페스트가 선언하고 호스트가 검사한다
  - ARKA: 없다. 확장이 전부 우리 코드이고 같은 번들에 있다
- [ ] **확장 배포** — 바깥에서 확장을 받아 설치한다.
  - VSCode: 마켓플레이스·게시자·버전·의존성
  - OpenClaw: ClawHub. 카탈로그·신뢰·서명
  - ARKA: 없다. **이것을 안 하기로 하면 기여 선언의 절반이 사라진다**
- [ ] **확장 관리 화면** — 무엇이 깔려 있고 무엇을 끌지 보여 준다.
  - VSCode: 전용 뷰
  - OpenClaw: 플러그인 목록 명령과 Control UI
  - ARKA: 없다

## 작업 대상

- [ ] **파일 읽고 쓰기** — 워크스페이스의 파일을 다룬다.
  - VSCode: `IFileService` + 갈아 끼울 수 있는 파일 시스템 제공자
  - OpenClaw: `read`·`write`·`edit`·`apply_patch` 툴
  - ARKA: `IWorkspaceFiles` 여섯 동작. 제공자 추상은 없다(디스크 하나)
- [ ] **파일 변경 감시** — 밖에서 바뀐 것을 알아챈다.
  - VSCode: 변경 종류(추가·수정·삭제)를 싣고 제외 규칙을 받는다
  - OpenClaw: 해당 없음
  - ARKA: 바뀐 경로만 싣는다. **무슨 일이 일어났는지는 안 실어서** 받는 쪽이 다시 읽는다
- [ ] **파일 트리** — 폴더를 펴고 접고 고르고 옮긴다.
  - VSCode: 다중 선택·인라인 이름 바꾸기·맥락 메뉴·폴더 접기
  - OpenClaw: 없다
  - ARKA: VSCode의 선택 규칙까지 본떠 있다. 이 축은 이미 따라왔다
- [ ] **검색** — 워크스페이스 전체에서 글자를 찾는다.
  - VSCode: 한 줄 안의 여러 매치를 각각 표현한다. 제외 패턴·바꾸기까지
  - OpenClaw: 해당 없음(웹 검색은 다른 축이다)
  - ARKA: 줄 하나에 위치 하나뿐이라 **같은 줄의 두 번째 매치를 표현할 수 없다**
- [ ] **소스 제어** — 변경을 보고 고르고 커밋한다.
  - VSCode: 제공자 추상 위에 git 확장. 이력·브랜치·원격까지
  - OpenClaw: 없다
  - ARKA: 상태·스테이지·diff·커밋. 최소 집합이다. **파일 트리가 git 상태를 모른다**
- [ ] **텍스트 편집** — 코드를 고친다.
  - VSCode: 이것이 본업이다. 언어 서버·자동완성·진단·포맷·접기·인레이 힌트
  - OpenClaw: 없다. 에이전트가 툴로 고친다
  - ARKA: CodeMirror로 글자를 고친다. 언어 지원은 없다
- [ ] **미리보기** — 파일을 글자가 아니라 그림으로 본다.
  - VSCode: 마크다운·이미지·오디오·비디오·노트북
  - OpenClaw: 캔버스
  - ARKA: 마크다운만
- [ ] **diff와 병합** — 두 판을 견주고 합친다.
  - VSCode: diff 편집기·3-way 병합·여러 파일 한 화면·일괄 편집 미리보기
  - OpenClaw: `diffs` 확장
  - ARKA: git diff를 글자로 보여 준다. 병합 화면은 없다

## 에이전트

- [ ] **대화** — 사람과 에이전트가 주고받는 단위.
  - VSCode: 채팅 뷰. 참가자(`@`)와 슬래시 명령으로 갈린다
  - OpenClaw: 세션. 키가 어디서 왔는지(채널·스레드)를 말한다
  - ARKA: 세션 목록과 탭. 참가자는 하나
- [ ] **실행과 턴** — 한 번 시킨 일이 끝날 때까지.
  - VSCode: 요청 하나에 응답 하나
  - OpenClaw: **턴**이 경계다 — 답 하나 + 거기 딸린 툴 호출들. 한 실행에 턴이 여럿
  - ARKA: 실행 경계만 있고 **턴 경계가 없다.** 모델이 몇 번 왕복했는지 셀 수 없다
- [ ] **스트리밍** — 다 되기 전에 흘려 보여 준다.
  - VSCode: 응답 조각과 진행 단계
  - OpenClaw: 메시지 갱신 이벤트와 툴 진행 갱신
  - ARKA: 답과 생각은 흘린다. **툴은 시작과 끝뿐이라 오래 돌면 화면이 조용하다**
- [ ] **툴 정의** — 모델이 부를 수 있는 것의 목록.
  - VSCode: 모델용 설명과 **사람용 설명이 갈려 있다.** 조건부로 켜고 끈다
  - OpenClaw: 툴 객체가 스키마와 실행을 함께 든다
  - ARKA: 이름·설명·입력 스키마 셋. 사람용 설명이 없다
- [ ] **툴 정책** — 어떤 툴을 내줄지 고른다.
  - VSCode: `when` 조건과 모델 선택자
  - OpenClaw: `tools.allow`/`deny`. **모델 호출 전에** 목록에서 뺀다
  - ARKA: 없다. 정의된 것이 전부 나간다
- [ ] **승인** — 위험한 일을 하기 전에 묻는다.
  - VSCode: **툴이 스스로 정한다.** 물을 말·안전도·자동 승인 가능 여부가 전부 타입에 있다
  - OpenClaw: 실행 승인을 채널로 보내고 답을 문자열로 파싱한다
  - ARKA: 실행 전체에 불리언 하나. 자유 텍스트로 묻는다. **무엇을 승인하는지 화면이 모른다**
- [ ] **모델 선택** — 어느 모델로 돌릴지.
  - VSCode: 모델 선택자와 사용량 표시
  - OpenClaw: 카탈로그·가격·장애 시 대체·프로바이더 예순
  - ARKA: 배선이 안 되어 있다 (TASK-36)
- [ ] **맥락 관리** — 프롬프트에 무엇을 넣을지 고른다.
  - VSCode: 첨부(파일·선택 영역)와 프롬프트 파일
  - OpenClaw: 전용 층(`context-engine`)과 압축
  - ARKA: 이벤트 로그 전체를 넘긴다. **길어지면 그대로 터진다**
- [ ] **장기 기억** — 대화가 끝나도 남는 앎.
  - VSCode: 없다(지시 파일이 대신)
  - OpenClaw: 전용 층에 구현 셋(코어·벡터·위키)
  - ARKA: 없다
- [ ] **스킬** — 필요할 때 읽는 지식.
  - VSCode: `chatSkills` 기여로 파일을 가리킨다
  - OpenClaw: `SKILL.md` 마크다운이 곧 능력. **목록만 프롬프트에 넣고 본문은 모델이 읽는다**
  - ARKA: 없다. 툴이 넷이라 아직 안 아프다
- [ ] **기록** — 무엇이 언제 일어났나.
  - VSCode: 채팅 기록
  - OpenClaw: 셋이 갈려 있다 — 대화 기록·실행 궤적·감사 원장(메타데이터만)
  - ARKA: 이벤트 로그 하나가 전부를 겸한다. 순번이 있어 재연결이 정확하다
- [ ] **하위 에이전트** — 에이전트가 에이전트를 부린다.
  - VSCode: 없다
  - OpenClaw: 하위 에이전트 툴과 다중 에이전트 라우팅
  - ARKA: 없다

## 바깥과의 연결

## 먼저 답할 갈림길 셋

목록을 훑으면 큰 갈림길이 셋이고, 나머지 판정이 여기에 딸려 온다.

1. **확장이 바깥에서 오는가.** 아니라면 확장 배포·확장 격리·확장 관리 화면이 한꺼번에 빠지고,
   기여 선언도 절반이 사라진다. 남는 값은 "조립부의 손목록이 순회가 된다" 하나다.
2. **툴이 워크스페이스 밖에 닿는가.** 닿는다면 웹 읽기·외부 툴 서버·승인·툴 정책이
   한 묶음으로 필요해진다. 안 닿는다면 넷 다 미룰 수 있다.
3. **대화가 길어지는 것을 감당하는가.** 감당해야 한다면 맥락 관리·기록·장기 기억·스킬이
   한 묶음이다. 지금은 이벤트 로그 전체를 프롬프트에 넣는다.
