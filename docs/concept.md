# ARKA

ARKA는 개인 워크스페이스 기반의 Integrated Development Environment(IDE)로 다음의 내용을 핵심 키워드로 삼는다.

- **Agent**: 에이전트를 통한 작업 수행이 주축이다
- **Knowledge & Retrieval**: 개인 지식 관리 시스템으로서, 사용자가 아는 것과 그 맥락을 에이전트와 공유한다
- **Archiving**: 사용자의 데이터를 개인 워크스페이스에 저장하도록 한다

## 차별성

- **폰에서도 되는 편집기.** 파일과 무거운 프로세스는 원격 노드에 두고 PWA(설치되는 웹앱)로 붙는다. 데스크톱과 기능이 같고 화면 크기에서 오는 편의만 다르다.
- **에이전트가 관제탑이 아니라 편집기 안에 있다.** 에이전트 전용 도구는 코드를 직접 만질 자리가 없고, 에디터에 얹은 보조 기능은 세션이 부속이다. ARKA는 세션과 파일 사이를 오가는 것이 기본 동선이다.
- **사용자를 모델링한다.** 사용자가 무엇을 알고 무엇을 모르는지를 맥락으로 들어, 설명 수준을 맞추고 틀린 전제를 먼저 경고한다. 코드베이스만 읽는 도구는 이것을 못 한다.
- **남는 자리가 내 것이다.** 대화와 산출물이 벤더 서버가 아니라 내 개인 워크스페이스에 쌓인다.

## 제품 원칙

- **결정은 사용자가, 경고는 에이전트가.** 사용자가 항상 옳다고 전제하지 않는다. 모르거나 틀릴 수 있으므로 에이전트는 정확한 맥락에 근거해 전문가로서 미리 경고한다.
- **대상은 개발자가 아니라 지식노동자 전체다.** 개발자라고 모든 개발 지식에 정통하지 않고 오개념이 있을 수 있다. 사용자가 무엇을 안다고 믿지 않는다.
- **코드 편집이 핵심이다.** 에이전트 관제용 도구가 아니다.
- **워크플로는 과하지 않고 자연스러워야 한다.** 에이전트 세션과 파일 에디터 사이를 자유롭게 오갈 수 있어야 한다.

## 전제

- 서버는 사용자 PC 한 대에서 돈다. 바깥에는 cloudflared Tunnel(바깥에서 이 PC로 들어오는 통로) + Cloudflare Access로만 연다. **앱은 인증을 모른다.**
- 클라이언트는 설치 가능한 PWA다. 앱 셸만 캐시하고 API는 캐시하지 않는다.
- 프로토콜 버전은 요청 헤더가 싣고 서버가 판단한다.
- 데스크톱이 본작업, 모바일이 보조작업이되 **기능은 동등하다**. 화면 크기와 인터랙션 방식에서 오는 편의만 다르다.
- 사용자는 한 명이다.

원본 아키텍처 문서는 저장소 밖에 있다. 리포에 넣지 않는다 — 한 번 통째로 넣었다가 리뷰 불가로 롤백한 전례가 있다. 리포에 남기는 것은 규칙(`docs/CONVENTIONS.md`)이다.

## 아키텍처 (v1)

- 전체 구조: **클라이언트 - PWA** / **서버 - 개인 원격노드** / **연결 - Cloudflare Tunnel + Access**
  - 클라이언트는 React 기반의 PWA로써 모바일과 데스크톱을 동시에 지원할 수 있도록 한다.
  - 파일과 무거운 프로세스는 모두 사용자의 원격 개인 노드에서 실행하는 **서버 방식**. (VSCode SSH Server와 유사)
- 코드의 핵심 구조 1: 마이크로 커널 구조
  - **플러그인 간 직접 참조 금지.** 모든 접근은 커널 레지스트리를 통해서만 한다.
  - **자체 Extension Host**: VSCode의 익스텐션 생태계(Open VSX 등)는 포기하고 **작은 자체 extension host**로 유지
- Leveraging VSCode OSS
  - 대부분의 v1 기능은 VSCode와 겹치되, 실제 사용자가 인터랙션하는 클라이언트를 재설계하는 부분이 크다.
  - VSCode의 검증된 계약을 벤치마킹하되, 우리가 원하는 기능에 맞춰서 단순화하여 가져온다.
  - **구조 결정은 VSCode의 대응 개념을 따른다** — contribution point(확장이 기능을 끼우는 자리)·command·service·extension host. 같은 것을 새 이름으로 부르지 않는다.
- VSCode 대비 변경 1: 에디터 코어 - **CodeMirror 6**
  - VSCode에서 제공하는 Monaco는 무겁고, 모바일을 지원하지 않는다.
  - 따라서, Mobile 지원 커버가 가능한 CodeMirror 6를 활용한다.

## 전송

**연결은 WebSocket 하나다.** 소켓 안에서 채널로 나눠 쓴다 — VS Code Server와 같은 모양이다. 끊김·재연결·유예가 한 곳에서 관리된다.

- **소켓은 밀어주기 전용이다** — 파일 감시 이벤트, 터미널 출력, 설정 변경. 거꾸로 올라가는 것은 **터미널 입력 하나**다. 키마다 요청을 보낼 수 없어서다
- **요청과 응답은 전부 HTTP다.** 디렉토리 목록, 감시 걸기, 터미널 만들기. 상관 id·타임아웃·재시도를 직접 만들지 않고, 프로토콜 버전도 요청 헤더에 그대로 실린다
- **파일 본문과 미디어도 HTTP다.** 소켓에 실으면 큰 것 하나가 지나는 동안 터미널 출력이 뒤에서 막힌다. 이미지·비디오는 브라우저가 직접 물어야 스트리밍이 된다
- **소켓 메시지는 전부 바이너리다.** 터미널 출력이 초당 수백 번 흐르는데 base64로 싸면 33% 부풀고 파싱이 쌓인다. 대가는 눈으로 못 읽는 것이라 디코딩 도구를 같이 만든다. **요청·응답이 HTTP에 있으므로 `contracts`의 zod 응답 계약은 그대로 산다**
- **프로토콜 버전이 안 맞으면 서버가 소켓을 끊고 새로고침시킨다.** 옛 클라이언트가 새 서버와 말하는 구간을 만들지 않는다. 더티 탭이 있으면 브라우저가 떠나기 전에 묻는다
- **클라이언트가 연결 id를 만들어 소켓과 HTTP 요청 헤더에 둘 다 싣는다.** 서버는 그 id로 "이 요청의 결과를 어느 소켓에 밀지"를 안다. 순서가 안 얽히고, 재연결해도 같은 id를 쓴다. 탭마다 다른 id다
- **다시 붙으면 클라이언트가 감시를 다시 건다.** 그 자리에서 현재 상태를 한 번 대조해 끊긴 동안 놓친 변경을 따라잡는다. 서버는 연결 단위 상태를 들지 않는다 — 터미널 세션만 예외다

## 범위

### v1 — "IDE의 확장"

#### v1.0 — 기본 셸과 편집

셸과 편집기까지다. **LSP·VCS·에이전트는 넣지 않는다.**

가르는 잣대는 하나다 — **커널은 "확장이 꽂힐 자리"를 가진 것이고, 나머지는 전부 확장이다.** 무엇을 하느냐가 아니라 꽂을 자리를 갖느냐로 정한다.

##### 커널 — 꽂을 자리를 가진 것

- **화면 뼈대** — 확장이 꽂히는 자리 그 자체다
  - 액티비티 바, 사이드바와 보조 사이드바
  - 에디터 그룹 — 탭, 분할, 끌어서 재배치
  - 패널
  - 구역 경계를 끌어 크기 조절
  - **탭 계약** — 커널은 탭 안의 `URI`와 더티 여부만 안다. 저장·되돌리기 같은 동작은 **확장이 명령 레지스트리에 등록해 두고 커널이 그걸 부른다**. 텍스트·PDF·`.db`가 전부 이 하나로 꽂힌다 — **VSCode의 "사용자 지정 편집기"와 "웹뷰"가 우리에게는 특별한 것이 아니라 기본 모양이다**
  - **무엇이 열려 있었는지는 서버가 적는다.** 새로고침해도 탭이 그대로 돌아온다 — 브라우저 안이라 새로고침이 일상이고 배포 때는 우리가 강제로 시킨다
  - **탭 목록은 한 벌이고 보여주는 법만 다르다.** 좁은 화면은 탭을 줄로 늘어놓지 않고 한 번에 하나만 보여준다 — 설정과 같은 해법이다
  - **어느 확장이 어느 파일을 여는지는 확장이 신고한다.** 켜질 때 자기가 여는 것과 우선순위를 커널에 내고, 커널은 그 목록만 보고 고른다 — **확장 이름을 모른다**
- **명령 레지스트리** — 확장이 명령을 등록하고, 아래 둘이 그 등록부를 읽는다
  - 명령 팔레트
  - 단축키 — 표 화면, 충돌 감지, 내보내기
- **설정 저장소** — 확장이 자기 설정 스키마를 기여한다. `settings.json`을 커널이 든다
- **테마 토큰** — 색 변수는 커널이 갖는다. 테마 *값*은 확장이 기여한다
- **워크스페이스와 `URI`** — 모두가 같은 좌표계를 쓴다
- **DI 컨테이너 · 이벤트 버스 · extension host** — 확장을 불러오고 잇는 장치
  - **확장은 매니페스트 없이 코드로 신고한다.** 확장마다 `register(api)` 하나에서 뷰·명령·여는 파일 종류·설정 스키마를 전부 등록한다. 선언과 코드를 가르지 않는다 — **가른 원래 이유가 "켜기 전에 알아야 한다"인데 우리 확장은 번들에 정적으로 들어 있고 셸이 뜨면 전부 켜진다**
- **앱 수명** — 업데이트, 다시 시작

##### 확장 — 나머지 전부

**텍스트 에디터도 확장이다.** 그래야 텍스트·PDF·`.db`가 같은 모양으로 탭에 꽂힌다. 텍스트만 커널에 두면 "왜 얘만 특별하냐"가 계속 남는다.

- **파일 시스템** — `file:` 스킴을 기여한다. 읽기·쓰기·목록·만들기·이름 바꾸기·옮기기·지우기, 그리고 감시
- **탐색기** — 사이드바 뷰 하나. 트리, 만들기·이름 바꾸기·옮기기, 여러 개 한꺼번에
- **텍스트 에디터** — CodeMirror 6. **LSP는 없다**
  - 커서와 선택
    - 다중 커서 — 커서를 여럿 두고 한꺼번에 고친다
    - 열 선택 — 네모 모양으로 집는다
    - 의미 단위 넓히기·좁히기 — 낱말 → 구문 → 블록으로 선택을 키운다
    - 낱말·낱말 조각 단위 이동과 삭제 — `camelCase` 안에서도 끊는다
    - 줄 단위 선택
    - 닻 기준 선택 — 한 점을 찍고 거기까지 집는다
    - 커서 이동만 되돌리기 — 글자는 그대로 두고 커서 자리만
    - Tab 키를 들여쓰기로 쓸지 포커스 이동으로 쓸지 전환
  - 글 고치기
    - 줄 복제·이동·삭제·정렬·중복 제거
    - 잘라내기·복사·붙여넣기
    - 텍스트를 끌어서 옮기기
    - 끌어놓거나 붙여넣을 때 무엇으로 바꿀지 고르기 — 이미지 파일을 놓으면 마크다운 이미지 문법으로
    - 들여쓰기 — 탭·스페이스 변환, 파일을 열 때 감지
    - 파일 끝 빈 줄 자동 삽입
    - 짝 태그 함께 고치기 — 여는 태그를 고치면 닫는 태그도
    - 값을 다음·이전 후보로 바꾸기 — `true` ↔ `false`
    - 코드 조각(snippet) — 자리표시자를 Tab으로 건너뛴다
    - 주석 토글
    - 이상한 줄끝 문자 처리
  - 찾기
    - 찾기·바꾸기 — 정규식, 선택 영역 안에서만
    - 커서 아래 낱말을 파일 전체에서 강조
    - 경로·URL을 눌러서 열기
    - 헷갈리는 유니코드 표시 — 보이지 않는 글자, 비슷하게 생긴 글자
  - 보기
    - 접기 — 블록 단위, 들여쓰기 기준, 구획 주석 기준
    - 붙는 스크롤 — 지금 있는 블록의 머리를 화면 위에 고정
    - 글꼴 크기 조절
    - 짝 괄호 강조
    - 색 값 옆에 색상판
    - 빈 에디터 안내 문구
    - 아주 긴 줄·큰 파일 다루기
- **프리뷰** — 파일 종류로 가른다. 각각이 탭 계약에 꽂히는 확장 하나다
  - 이미지 — `png` `jpg` `gif` `webp` `svg`
  - 오디오·비디오 — `mp3` `wav` `mp4` `webm`
  - **PDF — VSCode에 대응이 없다. 직접 만든다**
  - **`.db`(SQLite) — 대응이 없다. 직접 만든다**
  - 웹 페이지 — 파일이 아니라 URL이다. **원격 노드의 포트만 본다**(포트 열기와 짝이다). 바깥 사이트는 v3다
  - 오피스 문서(XLSX·Slides·PPTX)는 v1.0에서 다루지 않는다
- **검색**
  - 폴더 전체 찾기·바꾸기 — 정규식, 포함·제외 글롭
  - 검색 결과를 편집 가능한 문서로
  - 여러 파일을 한 번에 고치는 미리보기(bulk edit)
- **터미널**
  - 여러 개, 분할, 프로필
  - 셸 통합 — 명령 단위로 자르기, 종료 코드 표시, 출력으로 이동
  - 링크 감지 — 출력의 경로를 눌러 연다
  - 명령·경로 자동완성
  - 포트를 바깥으로 열기
- **언어 기본 15개** — 문법 색칠, 들여쓰기 규칙, 짝 괄호, 코드 조각. 언어마다 하나씩이다
  - 웹 — `html` `css` `javascript` `typescript`
  - 데이터·설정 — `json` `yaml` `xml` `dotenv` `sql` `shellscript`
  - 안드로이드 — `kotlin` `groovy`
  - 글 — `markdown` `latex`. 마크다운은 KaTeX·수식·GitHub Flavor를 함께 든다
  - 분석 및 딥러닝 — `python`
- **테마 파일** — Dark+/Light+ 기본, 파일 아이콘
- **설정 화면** — 커널에 등록된 스키마를 그린다
- **코드 조각 관리** — 사용자가 자기 것을 만들고 고친다
- **로컬 히스토리** — 저장할 때마다 자국을 남겨 되돌린다
- **언어 감지** — 확장자·내용으로 언어를 판정한다

##### `shared/` — 커널도 확장도 아니다

트리·목록 같은 공통 UI 부품이 여기 산다. **Primer에서 온다**. 아무것도 import하지 않는다.

##### 모델 — v1.0이 지는 규칙

**화면이 어떻게 생기든 바뀌지 않는 것들이다.** 판단이 갈리는 자리는 VSCode가 하는 대로 따랐다.

- **Workspace — 무엇이 작업 범위인가**
  - 루트는 서버(개인 원격 노드)의 경로다. 클라이언트에는 파일이 없다
  - 경로는 문자열이 아니라 `URI`로 가리킨다
  - 루트 밖은 보이지 않는다. 심볼릭 링크가 밖을 가리켜도 따라가지 않는다
  - **루트는 하나다.** 계약도 `root: URI` 하나로 둔다 — 배열로 열어 두지 않는다
  - **루트는 서버 설정으로 고정한다.** 앱 안에서 폴더를 여는 일은 없다 — 그래서 루트 밖을 보여주는 화면이 아예 없다
- **FileSystem — 읽고 쓰는 규칙**
  - 읽기·쓰기·목록·만들기·이름 바꾸기·옮기기·지우기. 전부 서버가 한다
  - 텍스트냐 아니냐가 **무엇으로 열지를 정한다** — 텍스트는 편집, 나머지는 보기
  - **크기 상한을 둔다.** 넘으면 열지 않고 알린다 — 값은 설정으로 뺀다. **그래서 파일은 항상 통째로 주고받는다**
  - **인코딩은 UTF-8 고정이다.** 읽고 쓰는 것이 항상 UTF-8 문자열이고 저장 경로에 분기가 없다
  - **줄끝은 파일이 가진 것을 보존한다.** 열 때 감지해 저장할 때 되돌려 놓는다. 새 파일은 LF다
  - **지우면 영구다. 휴지통을 두지 않는다** — 대신 지우기 전에 확인을 받는다
- **Watch — 바깥에서 바뀌는 것**
  - 열린 파일과 디렉토리를 둘 다 본다
  - 바깥이 바뀌었고 내가 안 고쳤으면 조용히 반영한다
  - **바깥도 바뀌고 나도 고쳤으면 아무것도 안 덮어쓴다.** 화면은 내 내용 그대로 두고 자동 저장이 켜져 있어도 그 파일만 멈춘다. **충돌은 사용자가 저장을 누를 때 정리한다** — 나란히 비교하거나 덮어쓴다
  - **열어 둔 파일이 사라져도 탭을 닫지 않는다.** 내용을 든 채 "사라졌다"고 표시하고, 저장하면 다시 만들어진다
- **Document — 편집 중인 문서**
  - **한 파일에 문서 하나.** 탭 둘이 같은 파일을 열면 같은 문서를 본다
  - 디스크 내용과 메모리 내용을 따로 든다. 둘이 다르면 dirty다
  - **손으로 저장하는 것이 기본이다.** 자동 저장은 설정으로 켠다 — VSCode의 기본값을 그대로 따른다
  - **되돌리기 스택은 저장을 넘어 살아남고 탭을 닫으면 사라진다.** 서버에 두지 않는다
  - **저장 안 한 편집은 클라이언트에만 있다.** 서버는 문서 상태를 들지 않고 파일만 다룬다 — 기기 사이로 이어받지 않는다
- **Terminal — 세션**
  - 세션은 서버에 산다. 클라이언트는 화면과 입력만 나른다
  - **클라이언트가 끊겨도 세션은 산다.** 서버가 PTY와 출력 버퍼를 들고 클라이언트는 붙었다 떨어진다 — 폰을 닫아도 빌드가 계속 돈다
  - **안 붙은 세션은 유예 시간 뒤 정리한다.** 그냥 끊긴 것과 일부러 닫은 것을 갈라 뒤쪽을 훨씬 짧게 둔다 — VSCode가 3시간과 5분으로 가르는 것과 같다. 값은 설정으로 뺀다
  - **출력 버퍼는 줄 수로 상한을 둔다.** 넘치면 앞에서 버린다 — 값은 설정으로 뺀다
- **Settings — 설정**
  - 서버에 산다. 기기가 여럿이므로 한 곳에 둔다
  - 기본값 위에 사용자값을 얹는다
  - **설정은 한 벌이다. 기기별 값을 두지 않는다** — 화면 폭에 따라 갈라지는 값만 둔다. 설정에 "기기"라는 개념이 없다
  - **바꾸면 즉시 듣고, 붙어 있는 모든 화면에 닿는다.** 서버가 변경을 밀어준다
- **전체에 걸리는 것**
  - 무거운 것은 전부 서버다. 클라이언트는 그리기만 한다
  - 앱 셸만 캐시하고 API는 캐시하지 않는다 — **끊기면 읽기도 안 된다**
  - **끊기면 편집을 막지 않는다.** 재연결을 시도하며 배너로 알리고, 저장이 실패하면 그때 알린다 — VSCode 원격이 하는 대로다

**열람 맥락이 여기 산다.** 에이전트가 사용자가 보는 것을 정확히 짚으려면 브라우저가 ARKA 안에 있어야 한다 — 바깥 브라우저 탭은 우리가 볼 수 없는 자리다. 길은 **원격 노드에서 진짜 브라우저를 돌리고 화면을 흘려보내는 것**이다. 클라이언트에 엔진을 넣는 길은 막힌다(브라우저 안이라 `fetch`가 CORS에 걸리고, 남의 사이트를 iframe에 넣으면 `X-Frame-Options`가 막는다).

**v1.0·v1.2가 아니라 여기인 이유** — 수주~수개월짜리다. 한글 입력(IME) 조합을 서버로 넘기는 것, 화면 대역폭, Chromium 한 대당 메모리 300~800MB, 임의 사이트의 JS를 내 PC가 돌리는 것에 대한 컨테이너 격리가 각각 따로 설계다. 앞 마일스톤에 얹으면 그 마일스톤을 삼킨다.
