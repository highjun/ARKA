# 주인 없는 규칙 — ADR이 재작성될 때 되살린다

여기 있는 커스텀 린트 규칙 여섯은 **끈 것이지 버린 것이 아니다.**

껐던 이유는 하나다 — **그 규칙을 낳은 ADR이 아직 새 번호로 옮겨지지 않았다.** 규칙은 결정이
낳는 것이고, 결정이 `docs/copy/`에 화석으로 있는 동안 규칙만 돌면 근거 없이 강제하는 셈이다.
`강제:`에 적을 자리가 없는 규칙은 어느 ADR도 책임지지 않는다.

| 규칙 | 무엇을 막았나 | 되살아날 곳(옛 번호) |
|---|---|---|
| `viewOnlyUsesViewModel` | `view/`가 `useViewModel` 외 훅을 쓰는 것 | 클라이언트 구조 (옛 0005) |
| `modelIsStateLibraryFree` | `model/`의 상태 라이브러리·React | 클라이언트 구조 (옛 0005) |
| `slicesAreSiblings` | 슬라이스끼리 직접 import | 클라이언트·서버 구조 (옛 0005·0007) |
| `fileNames` | 파일·폴더 이름 | 클라이언트·서버 구조 (옛 0005·0007) |
| `componentsHaveStories` | 스토리가 대상 옆에 없는 것 | 클라이언트 테스트 (옛 0008) |
| `testNamesKorean` | `it()` 이름이 영문인 것 | 한글 문서·클라이언트 테스트 (옛 0002·0008) |

**되살릴 때 함께 할 것**: 각 규칙에 `*.test.ts`가 붙어 있다(valid/invalid fixture) — 규칙이
죽어 있어도 초록이기 때문이다. `ops/lint/rules/`로 되돌리고 `ops/lint/index.ts`가 플러그인으로
등록하면 된다. **켜기 전에 위반이 0인지 실측한다** — 전건 위반인 규칙은 규칙이 아니라 백로그다.

`at()` 같은 경로 계산이 fixture를 저장소 루트 기준으로 푼다. 폴더가 옮겨지면 **케이스가 통째로
조용히 죽으므로**, 되살릴 때 테스트 개수를 세고 일부러 깨뜨려 무는지 본다.
