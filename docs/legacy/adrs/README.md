# 정비 전 ADR 스냅샷 (2026-09-09)

ADR 재검토(계획의 r0)를 시작하기 직전의 `docs/adr/` 20개와 `docs/ADR_CANDIDATE.md`·`docs/lint-plan.md`를 그대로 뜬 것이다. 재작성 중 원문과 대조하려고 둔다.

**정본이 아니다.** 결정의 정본은 언제나 `docs/adr/`이다(→ [CONVENTIONS.md](../../CONVENTIONS.md)의 `## ADR`). 여기 있는 것은 읽기 전용 화석이고, 고치지 않는다.

`docs/copy/adrs/`는 같은 내용의 백업이다.

**r0가 끝나면 두 디렉터리를 지운다** — 같은 내용이 세 곳에 있으면 어느 것이 정본인지 묻게 되고, 그게 이 정비가 없애려는 바로 그 문제다. git 이력이 이미 영구 보관하므로 그때는 `git show`로 충분하다.

## 번호를 리셋한다

새 `docs/adr/`의 번호는 **옛 번호와 무관하다.** 큰 결정부터 쌓으므로 번호가 중요도 순서를 담는다. 20개를 전부 재작성하는 마당에 번호만 보존하면 같은 번호에 다른 내용이 들어가 옛 인용이 *조용히* 틀린 것을 가리킨다 — 번호를 바꾸면 링크가 깨져서 드러난다.

규약 둘:

- **ADR이 랜딩할 때 그 인용도 같은 커밋에서 옮긴다.** 안 그러면 옛 번호가 새 결정을 가리키는 중간 상태가 생긴다. 새 번호가 아직 없으면 인용에서 번호를 **떼어** 둔다 — 틀린 번호보다 없는 번호가 낫다.
- **재정렬은 이번 한 번뿐이다.** 순서가 정보를 담는 순간 번호는 다시 못 바꾼다. 앞으로는 뒤에 붙이기만 한다.

| 옛 | 새 | 주제 |
|---|---|---|
| 0001 | **0001** | 패키지 셋과 pnpm workspaces (번호가 우연히 같다) |
| 0013 (일부) | **0002** | 루트에는 전역인 것만 산다 |
| 0013 (일부) | **0003** | 모든 것은 그것이 다스리는 대상 옆에 산다 |
| 0002 | 미정 | 주석과 문서는 한글로 |
| 0003 | 미정 | URI로 파일·리소스를 가리킨다 — 인용에서 번호를 떼어 뒀다 |

r0가 끝나면 이 표로 남은 인용을 일괄 대조하고, `adrFormat` 테스트의 "인용된 번호가 실재하는가"가 마지막 관문이 된다.
