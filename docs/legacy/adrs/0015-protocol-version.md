# ADR 0015: 프로토콜 버전은 요청 바디가 싣고, 서버가 판단한다

## 결정:
- 클라이언트·서버가 주고받는 계약에 **프로토콜 버전**을 둔다. 앱 버전과 독립적으로 움직이고, **구 클라이언트를 깨는 변경일 때만** 올린다.
- 버전은 **요청 바디**가 싣는다(`ProtocolVersioned`). 모든 요청 스키마가 이것을 확장한다.
- 스키마는 **특정 버전으로 고정하지 않고 양의 정수로 받는다.** 클라이언트가 사용자 기기에 캐시되는 PWA라 서버는 구 버전 요청도 당분간 받아줘야 하는데, 고정해두면 스키마 파싱 단계에서 걸러져 그럴 수 없다. **지원 여부는 서버가 판단한다.**

## 기각:
- **버전 없이 시작** — ADE 문서 §16의 대안이었다. PWA는 사용자가 새로고침하지 않으면 낡은 채로 남는다. 원격 배포([ADR 0014](0014-remote-access.md))에서는 폰에 캐시된 구 클라이언트가 새 서버를 치는 상황이 정상 경로다.
- URL 경로에 버전 두기(`/api/v1/...`) — 라우트가 버전마다 갈라져 같은 핸들러를 복제하게 된다. 우리는 대부분의 변경이 바디 모양이라 경로를 나눌 이유가 없다.
- 헤더에 두기 — zod 스키마 밖이라 검증이 두 갈래가 된다. 바디에 두면 계약 하나로 끝난다.
- 스키마에 버전을 리터럴로 고정 — 구 요청이 파싱 단계에서 죽어 서버가 "몇 버전이라 못 받는지"를 답할 수조차 없다.

## 상태:
**대체됨** — 전송 방식(요청 바디)은 [ADR 0017](0017-protocol-header.md)이 헤더로 바꿨다. 버전을 둔다는 것과 서버가 판단한다는 원칙은 유지된다. 아래는 2026-09-08 시점 기록이다.

승인됨. **다만 아직 배선되지 않았다.**

- `PROTOCOL_VERSION`과 `ProtocolVersioned`가 `contracts/src/common/version.ts`에 선언돼 있으나 **쓰는 곳이 0건**이다.
- 어떤 요청 스키마도 `ProtocolVersioned`를 확장하지 않고, 서버는 `protocolVersion`을 읽지 않는다.
- `/api/version`은 `builtAt`만 돌려주고 프로토콜 버전은 알리지 않는다.

**배선 시점은 원격 배포다.** 로컬에서는 클라이언트와 서버가 항상 같이 빌드되어 어긋날 일이 없지만, [ADR 0014](0014-remote-access.md)로 폰에 PWA가 캐시되는 순간 이 문제가 실제가 된다. 배포 전에 배선하거나, 배선하지 않기로 한다면 이 선언을 지워야 한다 — 쓰지 않는 계약이 남아 있으면 다음 사람이 "이미 되는 것"으로 오해한다.
