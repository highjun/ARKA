## 설명

[ADR 0008](../adr/0008-component-surface.md)은 props 바탕을 **`ComponentPropsWithoutRef<'x'>`**로 정했는데,
코드는 아직 `HTMLAttributes<HTMLXElement>`다(39곳). TASK-54가 `ref`·`style`·이름은 맞췄지만 바탕 타입은
남겨 뒀다 — 관심사가 다르고, 원소 클래스에서 태그 이름으로 가는 대응이 기계적이지 않아서다.

**차이가 실재한다.** `HTMLAttributes<HTMLAnchorElement>`에는 `href`가 없고
`ComponentPropsWithoutRef<'a'>`에는 있다. `disabled`·`type`·`value`도 같다. 지금은 그래서 원소
고유 속성을 쓰려면 소비처가 캐스트하거나 우리가 prop을 다시 선언해야 한다.

**기계적이지 않은 자리**가 둘이다. ① `HTMLAttributes<HTMLElement>`(13곳)은 어느 태그인지 타입이
말하지 않는다 — 렌더하는 JSX를 봐야 한다. ② `Tab`처럼 leaf/branch에 따라 태그가 갈리는 것
(`section`/`div`)은 바탕을 하나로 못 정한다. 그 둘은 판단이 필요하다.
## 인수 조건

- [x] `HTMLAttributes<`·`ButtonHTMLAttributes<`를 쓰는 props 선언이 **한 곳뿐**이고 린트가 그것을 드러낸다
- [x] 태그가 갈리는 컴포넌트는 어느 바탕을 골랐는지와 왜 그랬는지가 주석에 있다
- [x] `pnpm --filter ops check`가 초록이다

## 2026-09-14 — 42곳을 옮기고 한 곳을 예외로 남겼다

원소 클래스에서 태그 이름으로 가는 대응이 기계적인 30곳은 치환으로, 뜻을 봐야 하는 곳은 루트가
그리는 태그를 읽어 옮겼다 — `CodeBlock`→`figure`, `Message`→`article`, `TextEditor`→`section`,
`ActivityBar`→`nav`, `Markdown`→`div`, `Menu` 부품→`div`, `Menu.Trigger`→`button`.

**`0건`은 못 지켰고, 지키지 않는 것이 맞다.** `FileTree`는 항목이 없으면 `<div>`, 있으면
`<ul role="tree">`를 그린다. 이벤트 핸들러의 제네릭이 원소별이라(`ClipboardEventHandler<HTMLDivElement>`
≠ `<HTMLUListElement>`) 태그를 하나로 정하면 나머지 분기에서 거짓이 된다. 공통 조상으로 두고
사유를 적은 `eslint-disable` 한 줄로 드러냈다 — 규칙을 켰기 때문에 예외가 세어진다.

**곁들여 찾은 것:** `MenuProps`가 `HTMLAttributes`를 물려받고 있었는데 루트는 **자기 DOM을 그리지
않는다.** `className`·`id`·이벤트를 받는 것처럼 보이고 실제로는 Radix Root가 조용히 버렸다.
원소 바탕을 떼고 받는 것만 적었다.
