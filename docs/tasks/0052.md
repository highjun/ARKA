## 설명

2026-09-10에 `PreToolUse` 훅을 달았다가 **같은 날 걷어냈다.** 강제인 척하는 장치였기 때문이다 —
저장소가 전부 `highjun:highjun`이고 에이전트도 같은 사용자라, 설정이든 스크립트든 같은 손이
고칠 수 있다. 게다가 훅은 `Write`·`Edit`만 가로채는데 이 저장소의 편집은 거의 전부 셸이었다.

대신 **`ops/hooks/preCommit.ts`가 커밋 때 세어 보여준다.** 막지 않는다.

**진짜 강제는 저장소 밖에만 있다.** 조사해 둔 것:

| 층 | 에이전트가 뚫나 |
| --- | --- |
| git 훅 | 예 — `--no-verify` |
| 프로젝트 `.claude/settings.json` | 예 — 그 파일을 고친다 |
| `/etc/claude-code/managed-settings.json` | **아니오** — `sudo`가 암호를 요구한다(실측) |
| OS 권한(다른 소유자·컨테이너) | **아니오** |

managed settings는 프로젝트·사용자 설정이 덮어쓸 수 없다. **훅이 아니라 `permissions`로 적어야
한다** — 훅으로 하면 스크립트가 저장소 안에 남아 그것을 고치면 그만이다.

**지금 하지 않는 이유**: 막으려는 것이 악의가 아니라 부주의다. 이 저장소가 겪은 사고 셋은 전부
`git add -A`였고, 부주의는 드러내면 잡힌다. 악의를 막으려면 사용자가 `sudo`로 설치해야 하고
셸 구멍은 OS 층까지 가야 닫힌다.
