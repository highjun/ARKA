## 설명

view가 자기 안에서 목록 행과 배지를 직접 그리는 자리가 있다. [ADR 0007](../adr/0007-client-layers.md)이
`component/`를 props만 받는 자리로 정했으니, 그 조각은 스토리를 가질 수 있는 컴포넌트로 내려야 한다.
**view 안에 있는 컴포넌트만 내린다** — 후보 B(TASK-46)를 범위를 좁혀 채택한 첫 벌이다. view 자체의 스토리 범위(TASK-45)와 `view/`의 Primer 직접 import 0건(TASK-46에 남는다)은 이 라운드가 아니다.

- `SourceControlView`의 변경 파일 행과 상태 배지 → **`ChangeList`**(`.Item`). Primer `ActionList` + `.TrailingVisual`에 `Label`. `extensions/git/component/` 신설.
- `SearchView`의 결과 목록 → **`SearchResultList`**(`.Item`). `extensions/search/component/` 신설.
- `DiffTabView`의 줄별 `<pre>` → **`DiffView`**. Primer에 대응이 없다.
- `KeybindingsTabView`의 `<table>`/`<kbd>` → **`KeybindingTable`**. 키 표시는 Primer `KeybindingHint`.
- `core/commands/CommandMenuView.tsx`는 파일 이름과 export가 다르다 → `CommandContextMenu.tsx`.
- 같은 라운드에 `CommandPalette`의 탈출구 둘(`overlayClassName`·`container`)을 지우고(PortalProvider가 있다) 안의 `Dialog`를 `Overlay`로 개명한다. `NotificationList`·`CrashScreen`에 규약을 적용한다.

## 인수 조건

- [ ] `ChangeList`·`SearchResultList`·`DiffView`·`KeybindingTable`이 ViewModel을 모른다

## 2026-09-14 — 내렸다

넷을 내렸다 — `ChangeList`(`.Item`) · `SearchResultList`(`.Item`) · `DiffView` · `KeybindingTable`.
`git`·`search`에 `component/` 폴더가 생겼다. 넷 다 스토리와 하네스 넷을 갖는다.

**드러난 접근성 결함 둘.** `ChangeList`를 내리고 axe를 돌리자 뷰에 있을 때는 아무도 안 보던 위반이
잡혔다. ① 머리글을 `div`로 감싸 "전부" 버튼을 옆에 두었는데 그 `div`가 묶음의 `ul`에 직접 들어가
"리스트는 `li`만 담아야 한다"를 깼다. ② 누를 수 있는 행 안에 버튼을 넣어 `nested-interactive`가
걸렸다. 둘 다 Primer의 전용 부품(`GroupHeading.TrailingAction`·`ActionList.TrailingAction`)으로
고쳤다 — 후자는 Primer가 "행의 활성 영역 **밖**"에 두려고 만든 자리다.

이것이 [ADR 0010](../adr/0010-ui-verification.md)이 컴포넌트마다 하네스를 요구하는 이유의 실례다.
같은 마크업이 view 안에 있는 동안은 검사가 닿지 않았다.

곁가지로 `CommandMenuView.tsx`를 export 이름과 맞춰 `CommandContextMenu.tsx`로 바꾸고,
`CommandPalette`의 탈출구 둘(`overlayClassName`·`container`)을 지웠다 — 쓰는 곳이 0이었고 포탈
자리는 `usePortalContainer()`가 이미 안다. 안의 `Dialog`는 `PaletteDialog`로 개명했고 열림 상태를
손으로 든 `useState`에서 `useControllableState`로 옮겼다.
