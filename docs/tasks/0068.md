## 설명

`.github/dependabot.yml`이 TypeScript 메이저를 무시한다(#34). **막는 것은 하나뿐이다** —
`typescript-eslint`가 TS 7 을 **하드 거부한다**. 경고가 아니라 던진다:

```text
typescript-eslint does not support TS 7.0.
```

2026-09-14 실측(카탈로그를 `^7.0.2`로 올려 확인).

| | TS 7.0.2에서 |
| --- | --- |
| `tsc --noEmit` 네 패키지 | 통과 |
| client·server 빌드 | 통과 |
| 테스트 | 845개 통과 |
| **린트** | **죽는다** |

`typescript-eslint@8.70.0`(최신, alpha 포함)이 `typescript: >=4.8.4 <6.1.0`을 선언하고, 딸린
`ts-api-utils`도 TS 7 API에서 `Cannot read properties of undefined (reading 'Intrinsic')`로
깨진다 — 그 탓에 `ops/structure/` 스위트 둘까지 함께 죽는다(설정을 로드하면서).

**지금 올리면 잃는 것:** 린트가 이 저장소에서 구조 규칙을 강제하는 주 장치다 — 계층 zone,
파일·폴더 이름, 테스트 규율, 전역 제한, 타입 인식 규칙 셋.
메이저 하나를 위해 그걸 끄는 것은 손해다. 기성품을 쓰는 대가로 적어둔 "플러그인 하나가 늦으면
올림이 막힌다"가 정확히 이 경우다.

**기각한 우회로:** TS 6 API 옆에 두고 돌리는 side-by-side 설치. TypeScript 가 공식 문서에서
안내하지만 TypeScript 를 두 벌 두고 해석을 비트는 것이라, 막히는 것이 도구 하나뿐인 상황에서
치를 값이 아니다. 기다리는 편이 싸다.

추적: [typescript-eslint#10940](https://github.com/typescript-eslint/typescript-eslint/issues/10940).
