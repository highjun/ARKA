## 설명

IDirectoryTreeViewModel.ts:36과 CommandCenterRegistry.test.ts:6이 `arka/external-import-allowlist`가 import를 막는다고 적었지만 그런 규칙은 없다. tooling/eslint-rules에 있는 것은 fileNames·modelIsStateLibraryFree·slicesAreSiblings·viewOnlyUsesViewModel·testNamesKorean 다섯뿐이다. axe.tsx가 설치되지 않은 애드온을 인용한 것(TASK-32)과 같은 부류 — 주석이 존재하지 않는 강제 장치를 근거로 든다. 규칙을 만들거나 주석을 고친다. 되풀이되는 실수라 린트로 잡는 편이 낫다: 주석 안의 `arka/<이름>` 인용이 플러그인에 실재하는지 검사하는 규칙은 값이 싸다.

## 인수 조건
- [x] 주석의 `arka/*` 인용이 전부 실재하는 규칙을 가리킨다
- [~] 인용이 실재하는지 검사하는 린트 규칙 — 철회했다(아래)

## 작업 노트

거짓 인용 넷을 고쳤다 — `arka/external-import-allowlist`(없던 규칙) 둘, `arka/view-only-uses-view-model`
둘. 고친 방향이 "규칙을 만든다"가 아니라 **"규칙 대신 ADR을 가리킨다"**다. 주석이 규칙 ID를 들면
규칙을 끄거나 갈아탈 때마다 주석이 낡는데, 실제로 그래서 넷이 거짓이 됐다. 결정은 규칙보다 오래
산다 — 넷 다 `(→ ADR 0007)`로 바꿨다.

둘째 조건은 철회한다. 검사할 `arka/*` 인용이 남지 않았고(실재하는 자작 규칙은 `max-comment-lines`
하나다), 그 검사를 위해 자작 규칙을 새로 만드는 것은 [ADR 0011](../adr/0011-lint-off-the-shelf.md)이
금지한다. 같은 실수를 막는 것은 규칙이 아니라 결정 문장이다 — ADR 0011이 "인용하는 규칙 ID는
실재해야 하고, 강제가 아직 없으면 ADR을 가리킨다"로 담았다.
