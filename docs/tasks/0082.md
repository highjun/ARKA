## 설명

계약만으로 안 되는 자리가 있다 — 탭 순서, 트리 갱신, 명령 검색 같은 내부 알고리즘. 사람이 코드를 읽어야 하면 리뷰가 줄지 않는다.
정할 것: ① 알고리즘은 순수 함수 하나로 격리한다 ② 구현 전에 한 쪽짜리 노트(문제·접근·기각한 대안·불변식·경계)를 내고 사람이 승인한다 — 자리는 ADR 형식을 따르되 코드 옆 ③ 노트의 불변식마다 속성 기반 테스트 하나(fast-check) ④ 태스크가 "정독 대상" 파일을 미리 선언하고 하나를 넘으면 쪼갠다 ⑤ 노트의 절과 코드의 단계 이름이 1:1. 결정되면 ADR이 되고 이 태스크는 닫힌다.

## 인수 조건

- [ ] ADR이 있고 위 다섯 중 무엇을 택하고 버렸는지 적혀 있다
- [ ] fast-check가 client 또는 contracts에 있고 성질 테스트 선례 하나가 있다
- [ ] 태스크 템플릿(`ops/tasks/main.ts`)에 정독 대상 자리가 있다
