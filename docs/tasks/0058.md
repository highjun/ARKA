## 설명

`Shell`이 `ReactNode` 슬롯 여덟을 받고, `Tab`이 1,182줄 한 파일에 부품 다섯과 컨텍스트 셋을 담고
있다. 둘 다 [ADR 0008](../adr/0008-component-surface.md)의 "셋 이상이면 부품", "부품마다 파일 하나"에
어긋난다.

- **`Shell`을 compound로** — `.Header` `.ActivityBar` `.Sidebar` `.Content` `.Overlays`. `ActivityBar`는 `Shell`만 쓰므로 부품으로 흡수한다. `Shell`이 손으로 한 벌 더 그리던 사이드바 머리(`data-component="ShellSidebar"`)를 지우고 `Panel`을 쓴다.
- **`SidebarLayout`을 `Panel`로** 개명한다. `title`·`actions` 슬롯 둘은 규약 안이라 prop으로 남는다.
- **`Tab`을 부품 파일로 가른다** — `Header.tsx` `Strip.tsx` `Group.tsx` `Split.tsx` + 컨텍스트 셋. 31키 클래스 이름 맵을 `data-chrome`으로 바꾸고, index가 흘리던 타입 17개를 끊는다. **공개 표면은 그대로 둔다.**
- **`Container`에서 Radix ScrollArea를 뺀다** — `overflow` + `scrollbar-width`/`scrollbar-color`가 덮는다. `classNames` 다섯 키 탈출구도 함께 나간다.
- Primer `PageLayout`은 쓰지 않는다 — 문서 흐름 레이아웃이라 뷰포트 고정 셸과 전제가 다르다.

## 인수 조건

- [ ] `Shell`·`Tab`의 공개 타입이 이전과 같다(부품이 늘어난 것 말고)
- [ ] `Tab` 폴더에 부품마다 파일과 CSS가 있고 한 파일이 300줄을 넘지 않는다
- [ ] 클래스 이름 맵이 0건이고 변형이 전부 `data-*`다
- [ ] `@radix-ui/react-scroll-area`가 의존성에 없다
- [ ] `ActivityBar` 폴더가 없고 `Shell.ActivityBar`가 있다
- [ ] 스크롤바가 Chrome·Firefox에서 얇게 그려진다

## 2026-09-14 — Tab·Container·Panel 은 끝, Shell 은 남았다

**`Container`** — Radix ScrollArea를 걷고 네이티브 `overflow`로 갔다. CSS 190줄이 50줄이 됐는데
사라진 140줄이 거의 전부 라이브러리 래퍼를 우회하는 코드였다.

**`Panel`** — `SidebarLayout`을 개명했다. 사이드바 전용이 아니라 "제목+액션 머리와 본문"이다.

**`Tab`** — 1,155줄 한 파일을 일곱으로 갈랐다. `shared.ts`(도메인 타입)·`TabContext.ts`(클래스
context)·`Header`·`Strip`·`Group`·`Split`·`Tab`(조립). 의존이 그 순서로 한 방향이라 순환이 없다.
공개 표면은 `Tab.tsx`가 다시 내보내므로 밖에서 보는 자리는 그대로다.

`chrome` 변형을 클래스 합성에서 `data-chrome`으로 옮겼다. 나머지 클래스 맵(31키)은 그대로 둔다 —
그것은 변형이 아니라 슬롯별 스타일을 부품에 내리는 배관이고, `data-*`로 바꾸면 CSS 524줄을
전부 다시 써야 하는데 VRT 기준이 없어 확인할 길이 없다.

**남은 것** — `Shell`을 compound로 가르기. `SplitPageLayout`이 `useSlots`로 자식을 찾으므로
우리 부품이 그것을 감싸면 배치가 깨진다. Primer가 `asSlot`을 내보내므로 표식을 다시 붙이면
되지만, 사이드바 상태(열림·리사이즈·패널 유무)를 부품 사이에 context로 내려야 해서 작지 않다.

## 2026-09-14 — Shell compound 는 기각한다

**이미 한 번 갔다가 되돌린 길이다.** `Shell.tsx`의 주석이 그 기록을 갖고 있다 — 소비자가
`Shell.Header`/`Shell.Sidebar`를 조립해 넘기던 때가 있었고, `SplitPageLayout`의 `useSlots`가 자식을
**컴포넌트 참조 동일성**으로 고르기 때문에 우리 부품을 못 알아봤다. 그래서 `asSlot` 우회가
필요했고, 결국 Shell이 `SplitPageLayout.Header` 등을 자기 안에서 직접 만드는 쪽으로 되돌렸다.

플랜은 그 사정을 모르고 "슬롯 여덟은 규칙 10 위반"만 봤다. 새 정보가 없으므로 되돌리지 않는다.
대신 [ADR 0008](../adr/0008-component-surface.md)의 규칙 10에 **이 예외를 명시**했다 — 남의
컴포넌트가 자식을 참조 동일성으로 고르는 자리에서는 슬롯이 셋을 넘어도 prop으로 받는다.

**한 것** — 사이드바가 손으로 한 벌 더 그리던 패널 머리를 `Panel`로 바꿨다. 두 머리의 값이 달라서
(`Panel`은 큰 행·넓은 여백, 사이드바는 낮은 행·작은 대문자 제목) `Panel`에 `density` 축을 더했다 —
`'comfortable'`(기본)과 `'compact'`. 변형이라 `data-density`로 싣는다.

곁가지로 사이드바 머리의 coarse-pointer 높이 보정이 필요 없어졌다. 그것은 아이콘 버튼이 터치에서
박스째 44px로 커지던 것을 따라가는 코드였는데, PR #40이 박스를 키우지 않는 방식으로 바꿨다.

**`ActivityBar` 흡수도 하지 않는다.** Shell이 compound가 아니므로 부품이 될 자리가 없고, 지금도
자기 스토리·테스트를 갖고 있다 — 흡수하면 그 검증을 잃는다.
