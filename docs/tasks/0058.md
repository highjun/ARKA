## 설명

`Shell`이 `ReactNode` 슬롯 여덟을 받고, `Tab`이 1,182줄 한 파일에 부품 다섯과 컨텍스트 셋을 담고
있다. 둘 다 [ADR 0008](../adr/0008-component-surface.md)의 "셋 이상이면 부품", "부품마다 파일 하나"에
어긋난다.

- **`Shell`을 compound로** — `.Header` `.ActivityBar` `.Sidebar` `.Content` `.Overlays`. `ActivityBar`는 `Shell`만 쓰므로 부품으로 흡수한다. `Shell`이 손으로 한 벌 더 그리던 사이드바 머리(`data-component="ShellSidebar"`)를 지우고 `Panel`을 쓴다.
- **`SidebarLayout`을 `Panel`로** 개명한다. `title`·`actions` 슬롯 둘은 규약 안이라 prop으로 남는다.
- **`Tab`을 부품 파일로 가른다** — `Header.tsx` `Strip.tsx` `Group.tsx` `Split.tsx` + 컨텍스트 셋. 31키 클래스 이름 맵을 `data-chrome`으로 바꾸고, index가 흘리던 타입 17개를 끊는다. **공개 표면은 그대로 둔다.**
- **`Container`에서 Radix ScrollArea를 뺀다** — `overflow` + `scrollbar-width`/`scrollbar-color`가 덮는다. `classNames` 다섯 키 탈출구도 함께 나간다.
- Primer `PageLayout`은 쓰지 않는다 — 문서 흐름 레이아웃이라 뷰포트 고정 셸과 전제가 다르다.

## 인수 조건

- [ ] `Shell`·`Tab`의 공개 타입이 이전과 같다(부품이 늘어난 것 말고)
- [ ] `Tab` 폴더에 부품마다 파일과 CSS가 있고 한 파일이 300줄을 넘지 않는다
- [ ] 클래스 이름 맵이 0건이고 변형이 전부 `data-*`다
- [ ] `@radix-ui/react-scroll-area`가 의존성에 없다
- [ ] `ActivityBar` 폴더가 없고 `Shell.ActivityBar`가 있다
- [ ] 스크롤바가 Chrome·Firefox에서 얇게 그려진다
