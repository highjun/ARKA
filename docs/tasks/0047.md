## 설명

후보 C. `fixtures.ts` 규약을 2026-09-09에 철회했는데(`f7d82d5`, TASK-31) **두 질문을 하나로
뭉친 과잉 철회**였다.

1. 테스트와 스토리가 데이터를 공유해야 하나 → **아니오.** 이 판단은 유지한다. `FileTree`가
   근거다 — 스토리는 그럴듯한 트리 하나, 테스트는 단언마다 다른 최소 트리 셋.
2. 스토리의 값을 `fixtures.ts`로 뺄 것인가 → **뺀다.** 채택률 0이라는 근거는 후보 A 이전의
   측정이라 낡았다.

**`fixtures.ts`는 스토리가 쓰는 값**이다 — 샘플 데이터와 view 스토리가 주입할 **ViewModel 스텁**.
`Mock<Name>.ts`로 부르지 않는 이유는 이 저장소에서 `Mock*`이 **계약 스위트에 걸리는 구현**을
뜻하기 때문이다. 나누면 `Mock*` 규약이 오히려 선명해진다.

**자리는 쓰는 계층 옆**(`view/fixtures.ts`·`component/<Name>/fixtures.ts`). 슬라이스 루트는
안 된다 — 옛 ADR 0005가 `tokens.ts`를 기각한 이유(역방향 허브)가 그대로 적용된다.

**임계값을 두지 않는다.** 컴포넌트의 내용을 채우는 값이면 전부다 — 한 줄짜리도.

## 인수 조건

- [ ] `CONVENTIONS`의 fixtures 문장이 이 결정으로 바뀐다(지금은 철회 쪽만 담고 있다)
- [ ] 린트로는 못 잡는다는 것을 적어 둔다 — "스토리에 값을 두지 마라"는 정적 판정이 안 된다

## 2026-09-14 — 절반은 결정, 절반은 열려 있다

[ADR 0010](../adr/0010-ui-verification.md)이 이 태스크의 **질문 1과 같은 답**을 담았다 —
테스트와 스토리는 데이터를 공유하지 않는다. 근거도 같다(`FileTree`).

**질문 2는 그대로 열려 있다** — 스토리가 쓰는 값을 옆 파일로 뺄 것인가. ADR 0010은 그것을
기각하지 않았다. 다만 채택하면 ADR 0010에 한 줄이 더해져야 한다(지금은 스토리 파일이 하나라는
것까지만 정해져 있다). "채택률 0"이라는 옛 근거는 이 질문에 쓰지 않는다 — 그것은 *공유* 여부의
근거였다.
