## 설명

후보 B. view가 UI를 직접 그리고 있어서 **스토리 없는 컴포넌트의 대역**을 하고 있다.

**실측**: view 12개 중 **9개**가 `@primer/react`를 직접 import한다. `git`·`search`에는
`component/` 폴더가 아예 없다.

view가 배치만 하면 view 스토리에서 볼 것이 "배치"로 좁혀져 컴포넌트 스토리와 겹치지 않는다
(TASK-45와 맞물린다).

**순수 변환 함수 9개는 `view/shared.ts`로 뺀다.** 그중 6개는 애초에 view를 떠날 수 없다 —
`ReactNode`를 반환하거나(Model·ViewModel은 `ReactNode`를 갖지 않는다) 레지스트리 조회가
필요하다. 갈 수 있는 3개만 ViewModel로 보내면 변환이 두 군데로 갈라져 오히려 나빠진다.

**작지 않다** — view 스토리 35개 중 상당수가 바뀌고 `git`·`search`에 `component/`를 새로 만든다.

## 인수 조건

- [ ] `view/`에서 `@primer/react` 직접 import가 **0건**이 된 뒤 `no-restricted-imports`로 켠다
- [ ] `git`·`search`에 `component/`가 생기고 각 컴포넌트에 스토리가 있다
- [ ] 순수 변환 함수가 `view/shared.ts`에 모인다
