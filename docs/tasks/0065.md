## 설명

이 저장소에는 포매터가 없다(prettier·biome·dprint 어느 것도). ESLint에도 들여쓰기 규칙이 없고
stylelint는 CSS만 본다. 그래서 **코드 모양을 아무도 검사하지 않는다.**

실제로 사고가 났다. ref 전환(PR #39)에서 대량 치환 스크립트가 `Tab.tsx`의 본문 183줄을 2칸으로
납작하게 만들었는데, 타입 검사도 1000개 테스트도 린트도 전부 초록이라 그대로 main에 들어갔다.
다음 라운드에 그 파일을 열었을 때 눈으로 발견했다.

**기준은 "이 코드가 잘못되면 누가 알려주는가"다**(CONVENTIONS). 모양에 대한 답이 지금은 "아무도"다.
그리고 사람 눈은 1,100줄 파일의 들여쓰기를 리뷰에서 못 잡는다 — 못 잡았다.

고를 수 있는 답 둘. ① 포매터를 들인다(prettier가 표준이고 CI에서 `--check`로 돈다). ② ESLint
스타일 규칙(`@stylistic/eslint-plugin`)으로 들여쓰기만 본다. ①이 관례에 가깝고
ADR 0011의 "기성품을 쓴다"에도 맞는다. 대가는 첫 적용에서
저장소 전체가 한 번 다시 써진다는 것이다 — 그 커밋이 diff를 통째로 덮으므로 라운드 하나를
그것만으로 쓴다.
## 인수 조건

- [x] `check`가 코드 모양을 검사하고, 어긋난 파일에서 빨갛게 된다
- [x] 첫 적용(전체 다시 쓰기)이 다른 변경과 섞이지 않은 커밋 하나다
- [x] 어느 도구를 왜 골랐는지가 ADR 0011에 한 줄 더해진다

## 2026-09-14 — prettier 를 들였다

①을 골랐다. `ops/prettier.config.ts`이고 **기본값과 다른 것은 `printWidth` 하나**(120)다 —
실측 분포가 p50=34·p90=103·p95=120·p99=139라 기본값 80이면 3분의 1을 다시 쓰면서 JSX props가
세로로 길어진다.

**마크다운은 대상이 아니다.** prettier는 표를 **글자 수**로 정렬하는데 한글은 두 칸 폭이라
파이프가 눈에서 어긋난다(실측). 마크다운은 `markdownlint`가 든다.

관문은 `--check`만 한다 — 고치는 것은 `pnpm --filter ops run format`이다. 관문이 남의 파일을
조용히 고쳐서는 안 된다.
