## 설명

ADR 0009에 따라 **Primer에 이미 있는 것을 우리가 만든 자리**를 갈아탄다.
이름만 바꾸는 겹은 지우고, 없는 축을 더하는 겹만 남긴다.

- 지우고 Primer를 직접 쓴다 — `Heading`(우리 것은 `level` 하나였다), `Link`(`tone`이 `Text`와 어긋나 있었다), `ModeToggle` → `SegmentedControl`, `UpdateBanner` → `Banner`.
- `Dialog`(`.Actions`)를 Primer `Dialog`로 옮기고 **확인 흐름은 `useConfirm()`**(`Promise<boolean>`)으로 바꾼다. `DialogTone`이 하던 일은 `confirmButtonType`이 한다. `@radix-ui/react-dialog` 의존성이 나간다.
- view 넷이 손으로 가운데 정렬하던 빈·로딩·에러 자리를 `Blankslate`+`Spinner`로 바꾼다. 자작 `Blankslate`를 만들지 않는다.
- **남기는 겹 둘** — `Text`는 Primer `Text`에 없는 `tone`을 더하므로, `IconButton`은 우리 아이콘 id를 잇므로 남는다. Primer `IconButton`을 직접 가져오던 여섯 곳을 우리 것으로 돌리고 직접 import를 린트로 막는다.

## 인수 조건

- [ ] `@radix-ui/react-dialog`가 의존성에 없다

## 2026-09-14 — 첫 벌(PR #40)과 `ModeToggle` 기각

**첫 벌**은 모양이 바뀌지 않는 것만 담았다 — 죽은 `Link` 삭제, `component/index.ts` 배럴 넷 제거,
Primer `IconButton` 직접 import 다섯을 우리 겹으로, 그리고 그것을 막는 린트.

**`ModeToggle` → `SegmentedControl`은 기각한다.** 쓰이는 자리가 셸 헤더의 해/달 아이콘 토글
하나인데, `SegmentedControl`은 두 선택지를 나란히 보여주는 컨트롤이라 폭이 훨씬 넓다. Primer에
두 상태 아이콘 토글이 없으므로 ADR 0009의 "둘 다 없으면 만든다"에
해당한다. `ModeToggle`을 남긴다.

덤으로 `ModeToggle`은 **`IconButton` 겹 규칙의 유일한 예외**가 됐다 — 터치 영역을 박스 확대가
아니라 `::after` 오버레이로 넓히는데, 헤더에 놓이는 컨트롤이라 박스가 커지면 옆을 밀어낸다.
그 과정에서 드러난 `data-component` 겹침 문제는 TASK-64로 뺐다.

**둘째 벌(PR #41)** — `Heading`과 `UpdateBanner`를 Primer로. 둘 다 크기·모양이 바뀐다.

- `Heading`: 우리 것은 `level`이 시각 크기까지 정했다(level 1 = 2.5rem, level 2 = 2rem). Primer는 `as`(문서 구조)와 `variant`(크기)를 가른다 — 접근성 관점에서 그것이 맞다. 크기만 바꾸려고 레벨을 고르는 일이 없어진다. 대응: 페이지 제목 `as="h1" variant="large"`(2rem), 구역 제목 `as="h2" variant="medium"`(1.25rem)
- `UpdateBanner`: 고정 문구만 담은 겹이라 지웠다. `ShellView`가 Primer `Banner`를 직접 그린다. `role="status"`를 남긴 것은 이 띠가 나중에 나타나는 것이라 나타난 사실이 읽혀야 해서다 — Primer `Banner`는 기본이 랜드마크라 그것만으로는 안 읽힌다

**셋째 벌** — `Dialog`를 Primer로, 빈·로딩·에러 상태를 `Blankslate`로.

- 확인 흐름은 `ConfirmationDialog`를 **선언형으로** 쓴다. `useConfirm()`은 쓰지 않는다 — 그것은 훅이고 ADR 0007이 "`view/`가 부르는 훅은 `useViewModel` 하나"로 정했다. 플랜이 `useConfirm()`을 적었지만 그쪽이 규칙과 어긋난다. 상태는 지금처럼 ViewModel(`pendingTabClose`·`deleteTargets`)이 들고 view는 조건부로 마운트한다
- 단일 확인 알림(파일시스템 실패)만 `ConfirmationDialog`가 맞지 않는다 — 그것은 취소 버튼을 항상 낸다. 거기는 Primer `Dialog`에 `footerButtons` 하나와 `role="alertdialog"`를 썼다
- 잃은 것: 아이콘과 `tone`. 심각도는 `confirmButtonType="danger"`가 말한다. 얻은 것: 포커스 트랩, `danger`일 때 취소에 초점이 가는 기본값, Escape·배경 클릭 처리
- 빈·로딩·에러를 손으로 가운데 정렬하던 여섯 자리를 `Blankslate`로 바꿨다. `.center`/`.loading` CSS 클래스 셋과 인라인 style 상수 둘이 함께 나갔다
