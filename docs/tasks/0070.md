## 설명

텍스트 탭 provider는 열 때 `fileContentModel.open(path)`로 읽지만, 탭이 닫혀도 `close(path)`를 부르는 자리가
없다 — 열었던 파일의 버퍼와 감시가 남는다(옛 코드도 같았다). `TabSystem`은 탭이 빠지면 자식 컨테이너를
dispose하지만 descriptor는 그냥 버린다.

제안 — `TabDescriptor.dispose?(): void`. 탭이 목록에서 빠질 때 `TabSystem`이 부른다. 계약 검토가 먼저다
(→ `docs/contracts/workbench.md` TabSystem 절, 구멍 W5).

## 인수 조건

- [ ] 계약에 `dispose?`가 실린다
- [ ] `TabSystem.#sync`가 빠진 탭의 descriptor를 dispose한다 — 테스트
- [ ] 텍스트 provider가 `fileContentModel.close(path)`를, 미리보기 provider가 `previewModel.close(path)`를 부른다
