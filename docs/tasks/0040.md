## 설명

ADR 0001이 "패키지 간 참조는 workspace 패키지명(from \"contracts\")으로 한다"고 정했는데 아무것도 강제하지 않는다. eslint.config.ts의 zone은 client↔server·contracts↛둘의 방향만 막고, 상대경로 ../../../contracts/src/...는 그대로 통과한다. 실측 결과 지금 위반이 0곳(패키지명 54곳, 상대경로 0곳)이라 "위반 0에서 켠다"는 원칙에 맞는 상태다. 규칙이 죽어 있어도 초록이므로 켤 때 일부러 깨뜨려 무는지 확인한다.

## 인수 조건
- [ ] 패키지 경계를 넘는 상대경로 import가 린트에 걸린다
- [ ] tooling/eslint-rules/*.test.ts에 valid/invalid fixture가 있다
- [ ] 일부러 깨뜨려 규칙이 실제로 무는 것을 확인했다

## 작업 노트

2026-09-09: contracts 참조가 맨이름 "contracts"에서 "#contracts"(imports 필드)로 바뀌었다. 규칙은 "패키지 경계를 상대경로로 넘지 않는다"를 잡으면 된다. 실험으로 tsc·vitest·esbuild·vite·eslint·test/contract 일곱 경로 전부 #contracts를 해석하는 것을 확인했다.
