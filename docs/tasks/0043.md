## 설명

ADR 0002의 `강제:`가 지금 `리뷰` 둘뿐이다. 루트에 파일이 하나 늘어나는 것을 보는 기계가 없다.

목록이 아니라 **사유표**를 잠근다 — 항목마다 "왜 전역인가"를 한 문장으로 달고, 실재하는 집합과 양방향으로 대조한다. 실재하는데 표에 없으면 "사유를 적고 승인받아라", 표에 있는데 없으면 삭제도 잡힌다. 항목을 늘리려면 사유를 써야 하고 그 문장이 diff에 뜨는 것이 이 장치의 값이다.

실재 집합은 `readdirSync(루트)`에서 `.git`과 `git check-ignore`가 무시하는 것을 뺀 것이다. 커밋 전 추가도 잡히도록 `git ls-tree`가 아니라 파일 시스템을 읽는다.

**이 장치는 승인을 강제하지 않고 눈에 띄게 만든다.** 사유표를 함께 고치면 초록이 되므로, 실제 승인은 그 diff를 사람이 보는 것이다. 사전 차단이 필요하면 Claude Code `PreToolUse` 훅이 둘째 층이지만 에이전트에게만 걸린다.

내용은 잠그지 않는다 — `package.json` 해시를 잠그면 의존성 범프마다 빨간불이 뜨고 사람이 빨간불에 익숙해진다. 루트 `package.json`의 `scripts` **키 이름**만은 성격이 같고(전역 명령의 표면) 범프에 안 걸리므로 함께 잠글지 검토한다.

### 켜기 전에 걸리는 것

- `.claude/`가 추적도 `.gitignore`도 아니다. 켜는 순간 첫 위반이 된다. `PreToolUse` 훅을 쓰기로 하면 `settings.json`은 추적해야 해서 판단이 갈린다.
- `ops/vitest.config.ts`의 `include`는 2026-09-10에 `**/*.test.ts`로 넓혔다. `task.ts`에 테스트가 없다는 것은 그대로다.

- [ ] 사유표에서 항목 하나를 지우면 빨갛다 (양방향 대조)
- [ ] `.output/`·`node_modules/`를 만들어도 초록이다 (무시되는 것은 대상이 아니다)
- [ ] `.claude/`의 자리가 정해져 있다 — `.gitignore`이거나 사유표의 한 줄이거나
- [ ] ADR 0002의 `강제:` 첫 줄이 `리뷰`에서 `테스트`로 바뀌었다

## 2026-09-14 — 사유표를 `ops/structure/root.test.ts`에 뒀다

설계한 대로 **사유표와 실재 집합을 양방향으로 대조한다.** 루트에 파일을 하나 만들면 "사유를 적고
승인받아라"로 읽히는 실패가 나고, 표에서 항목을 지워도 잡힌다. 파일 시스템을 읽으므로 커밋 전
추가도 걸린다.

`.claude/`는 걸림돌이 아니었다 — 지금 `.gitignore`에 있어서 `git check-ignore`가 걸러 낸다.
내용은 잠그지 않았다(의존성 범프마다 빨간불이 뜨면 사람이 빨간불에 익숙해진다). 루트
`package.json`의 `scripts` 키 이름도 잠그지 않았다 — `eslint-plugin-package-json`이 형태를 보고,
전역 명령이 늘어나는 것은 사유표가 아니라 그 파일의 diff 가 보인다.
