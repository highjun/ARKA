## 설명

마크다운을 **채팅에서 안 그린다.** 에이전트 답이 `text`로 와서 그대로 찍힌다. 지금 렌더링은 파일
미리보기 탭 하나뿐이고 방식이 HTML 문자열(marked+DOMPurify)이다.

많이 쓸 곳이 채팅이고 거기서 필요한 것이 **상호작용**이다 — 코드 블록 복사, 파일 링크로 워크스페이스
열기, 체크박스. HTML 문자열에는 그것을 붙일 자리가 없다. react-markdown은 요소마다 컴포넌트를 꽂는
표준이라 이미 복사 버튼을 가진 `CodeBlock`이 그대로 `code` 요소가 된다.

- `shared/component/Markdown` 신규 — react-markdown + remark-gfm. props는 `source`와 `components?`(요소 덮어쓰기 — view가 파일 링크 열기를 꽂는 자리).
- `code`만 `CodeBlock`으로 바꾸고 나머지 원소는 `Markdown.module.css`가 입힌다. **raw HTML을 켜지 않는다** — 그래서 정화기가 필요 없다.
- `Message` 본문과 `StepBlock` 도구 출력, 미리보기 탭이 모두 이것을 쓴다. `MarkdownPreview`와 `renderMarkdown.ts`, `marked`, `dompurify`가 나간다.
- 스트리밍 중 메시지마다 다시 파싱한다 — 메시지 단위 memo로 막는다.

## 인수 조건

- [ ] `marked`·`dompurify`가 의존성에 없고 `renderMarkdown.ts`가 없다
- [ ] 채팅 메시지에서 코드 블록이 그려지고 복사가 된다
- [ ] 미리보기 탭과 채팅이 같은 마크다운에 같은 그림을 낸다
- [ ] `<script>`가 든 마크다운이 스크립트로 실행되지 않는다(테스트)
- [ ] 메시지 목록이 긴 상태에서 스트리밍 중 재렌더가 메시지 하나로 묶인다
