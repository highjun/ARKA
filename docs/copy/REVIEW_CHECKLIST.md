# 리뷰 체크리스트

사용자가 `main` 대비 48커밋을 "의도대로 구현되었는지" 판정하는 자리다. **판정은 전부 사용자가 한다** — 에이전트는 자료를 준비할 뿐이고, Accept/Reject를 스스로 정하지 않는다.

## 유닛

유닛은 두 종류다.

| 종류 | 예 | 무엇을 보는가 |
|---|---|---|
| **묶음** — 폴더 | `extensions/filesystem/component/` | 분해가 맞는가. 하위가 잘 나뉘었는지, 있어야 할 것이 있고 없어야 할 것이 없는지, 이름과 경계가 맞는지 |
| **낱개** — 그 안의 하나 | `extensions/filesystem/component/FileTree` | 계약 리뷰 + 구현 리뷰 + (UI면) 시각 검토 |

**묶음을 먼저 본다.** 분해가 틀렸으면 낱개를 볼 이유가 없다 — 하나씩 승인해놓고 "이건 셋이 아니라 둘이었어야 한다"가 나오면 앞의 승인이 무의미해진다.

## 강도

| 강도 | 대상 | 하는 일 |
|---|---|---|
| **정독** | 모든 묶음 유닛, `contracts/**`, `model/I*.ts`, `viewmodel/I*.ts`, `index.ts`, 린트·tsconfig 설정 | 계약 + 구현 + (UI면) 시각 |
| **훑기** | `model/`·`viewmodel/` 구현, `infra/`, 테스트 | 경로와 한 줄 요약까지 |
| **도구 위임** | 계층 경계, 파일명, import 방향, 테스트 이름 | 위임 근거만 적고 사람은 안 본다 |

묶음이 전부 정독인 이유 — 분해·경계·이름은 린트가 못 잡는다. `arka/file-names`는 형식만, `arka/slices-are-siblings`는 방향만 본다. **"이 셋으로 나눈 게 맞는가"는 사람만 판정할 수 있다.**

## 판정

`Accept` / `Reject` / `조건부 승인`(지금 통과, 후속은 `docs/tasks/`로 — 루프를 막지 않는다) / `재검토 대기`(수정이 머지되어 다음 라운드에서 델타만 본다).

`Accept`이면 그 시점 커밋 sha를 적는다. **UI 유닛은 그때 VRT 기준 이미지를 만든다**(`pnpm --filter client test:vrt -g "<스토리 id>" --update-snapshots` — **그 스토리 하나만**) — 승인 전에는 기준이 없고, 없는 것은 실패가 아니라 건너뜀이다. 승인 뒤 그 유닛이 바뀌었는지는 `pnpm run review:status`가 본다 — 소스에 완료 주석을 달지 않는다(ADR 0004의 주석 4종에 없고, 코드가 바뀌어도 주석은 남아 조용히 거짓이 된다).

## 검토 라운드

`main`에 머지 가능한 상태로 만드는 것이 목표다. 한 검토 라운드 = 슬라이스 하나(또는 그에 준하는 묶음)이고, 그동안 base는 동결된다. 라운드가 끝나면 base가 전진한다.

- **작업 라운드**(CLAUDE.md) = 한 관심사 = 한 커밋. 아래의 라운드와 다른 말이다.
- **검토 라운드**(`r1`·`r2`…) = base를 한 번 동결했다 전진시키는 구간.

순서는 되돌리기 비싼 것부터 — `contracts/` → `core/` → `workbench/` → `extensions/*` → `shared/` → 서버.

## 기록 규칙

- 이 파일의 표는 **통합 에이전트만 쓴다.** 수정 에이전트는 열지 않는다.
- 지적 원문은 여기가 아니라 **backlog 태스크**에 남긴다(CLAUDE.md: 산문 백로그를 다른 문서에 쌓지 않는다). 표에는 태스크 ID만 링크한다.
- 아래 "기록"은 append only.

## r0 — docs/adr/ (ADR 정비)

20개를 하나씩 다시 본다. **ADR 하나마다 내용 판정(1차) → 형식 적용(2차) → 확인(3차)** 을 이어서 한다. 정비 전 원문은 `docs/legacy/adrs/`에 떠 두었다.

처음엔 "20개 전부 1차 → 전부 2차"로 잡았다가 바꿨다. 내용 판정이 끝난 ADR을 형식까지 바로 옮기면 (1) 판정이 신선할 때 쓰므로 맥락을 다시 불러올 필요가 없고, (2) **템플릿 자체가 첫 ADR에서 시험된다** — 20개를 다 판정한 뒤에 `맥락:`·`강제:`가 실물에 안 맞는 것을 알면 늦다. 형식을 먼저 일괄로 바꾸면 안 되는 이유(사용자가 방금 다시 쓴 글을 읽고 내용을 판정하게 된다)는 그대로 유효하다 — 순서는 어디까지나 내용이 먼저다.

`tooling/adrFormat.test.ts`는 20개가 다 옮겨진 뒤에 켠다(위반 0에서 켠다).

1차에서 묻는 5문항 — ① 결정이 아직 유효한가 ② 결정문이 실측과 맞는가 ③ 무엇이 강제하는가 ④ 본문에 "현재 코드가 어떻다"가 있는가 ⑤ 아무도 인용 안 하는데 살릴 값어치가 있는가.

| # | ADR | 1차 내용 | 2차 형식 | 강제 | 후속 |
|---|---|---|---|---|---|
| 1 | 0007 서버·contracts feature 우선 | **Accept** | 대기(열린 것 둘) | 린트 5 / 아무도 4 | TASK-38·39, 후보 D·E |
| 2 | 0001 패키지 셋·pnpm workspaces | **Accept** | **완료** | 린트 3 / 아무도 1 | TASK-40·41 |

## 기록

### 0007 — 서버와 contracts는 feature 우선으로 나눈다
- **①** 유효. feature로 갈리는 구조가 맞다
- **②** `결정:`은 맞다. `상태:`의 4항목은 전부 거짓이었다 — `services/` 있음, `implements` 6건, `domain/` 9개 파일. 0019 이후 갱신되지 않았다
- **③** 린트 — `arka/slices-are-siblings`, 계층 방향 zone 3종(`domain`·`infra`·`runtime`/`services` 보호), 패키지 경계 zone. **아무도** — `index.ts` 공개 표면 최소화 / feature 간 "이벤트로 소통" / 빈 레이어 금지 / zod 원본 원칙
- **④** 있음 → 2차에서 4항목 전부 삭제, 태스크로 이동
- **열린 것**: `services/`의 조건, `agent`에만 인터페이스가 있는 것이 규칙인지 드리프트인지
- **딸린 결정**: 후보 E(세 패키지 폴더 어휘 통일, "마이크로커널의 전단계"), 후보 D(계층 이름으로만 부른다)

### 0001 — 패키지는 contracts·client·server 셋이고 pnpm workspaces로 묶는다
- **①** 유효. 기각 항목에 재검토 조건이 명시돼 있다 — *"5개 이상 + CI 지연이 생기면 재검토"*. 지금 3개라 조건 미달
- **②** **주장 다섯 개가 전부 참이다.** 패키지 3개 ✓ / `pnpm workspaces` ✓ / 패키지명 참조 54곳·상대경로 0곳 ✓ / `main` 필드 해석 ✓ / tsconfig `paths` 0개 ✓. 드리프트 로그가 없어 낡지 않은 13개 중 하나다
- **③** 린트 — zone(`contracts`↛`client`·`server`), zone(`client`↔`server`), `lint:config`(tsconfig `paths` 금지 — 기각 항목을 직접 강제). **아무도** — "패키지명으로 가져온다". 상대경로 `../../../contracts/src/…`는 zone을 통과한다. **위반이 0곳이라 지금 켤 수 있다**(TASK-40)
- **④** 없음. `승인됨.` 한 줄뿐
- **⑤** 피인용 2곳(`CONVENTIONS.md:71`·`lint-plan.md:40`)이라 고아 아님
- **대가**: `contracts`의 `main`이 `./src/index.ts` — 빌드 산출물이 아니라 **TS 원본**이다. 소비자가 전부 TS 도구라 지금은 문제없지만, JS만 쓰는 곳에서 소비할 수 없고(npm 배포 불가) 소비자가 `contracts`의 타입 오류까지 함께 컴파일한다. 2차에서 `대가:` 절에 적는다
- **맥락**: 결정문 첫 불릿 *"서버와 클라이언트가 같은 타입을 공유해야 한다"* 가 그대로 `맥락:`이 됐다. 템플릿이 예측한 대로 결정문에서 **꺼낸 것**이라 총량이 안 늘었다
- **`#contracts` 실험**: `imports` 필드로 `"#contracts": "contracts"` 한 줄. **일곱 툴체인 전부 통과** — tsc(패키지 2개 + `test/contract` 별도 tsconfig)·vitest(패키지 2개 + 루트)·esbuild 서버 단일 번들·vite 클라이언트 빌드·eslint. 54곳 전부 전환했다. 맨이름 `"contracts"`가 서드파티와 구분되지 않는다는 것이 이유이고, `#`은 이 저장소에서 이미 `#core/di`·`#components/common`로 "우리 것" 표시다
- **2차 완료** — 14줄 → 27줄(상한 40). 늘어난 14줄의 정체: `맥락:` 1 + `대가:` 1 + `강제:` 표 6 + 빈 줄. **결정·기각은 한 글자도 안 늘었다.** 제목을 명사구("pnpm workspaces 모노레포")에서 결정을 서술하는 문장으로 바꿨다. 파일명은 그대로 둔다 — 바꾸면 인용 2곳이 깨지고 얻는 것이 없다
