# ADR 0015: 사람은 자리와 판단만 승인하고, 나머지 PR은 기계와 리뷰 에이전트가 들인다

## 맥락:
모든 PR에 사람 승인 1개를 걸자(→ [ADR 0003](0003-approval-outside-src.md)) 두 가지가 같이 왔다 — 라운드를 잘게 가르면 승인이 잦아 사람이 지치고, 지치지 않으려 묶으면 수천 줄짜리 PR이 되어 diff를 읽지 못한 채 승인하거나 통째로 되돌린다. 리뷰 단위와 사람이 개입하는 단위가 같은 것이 원인이다.

## 결정:
- **PR은 전부 거치되, 사람 승인은 자리로 정한다.** CODEOWNERS에 적힌 경로(계약·공개 표면·결정·설정·배치)를 건드린 PR만 사람이 승인한다. 그 밖은 필수 검사가 초록이고 리뷰 에이전트가 이의를 남기지 않으면 자동으로 들인다.
- **판단이 든 PR은 사람이 본다.** PR 본문 첫 절은 「결정한 것」이다. 비어 있지 않으면 needs-human 라벨을 달고 사람 승인을 기다린다. 판단 없는 PR이 대다수여야 정상이다 — 아니면 태스크의 인수 조건이 느슨한 것이다.
- **PR에는 크기 상한이 있다.** 넘으면 필수 검사가 빨갛다. 상한 값은 파이프라인이 정본이다.
- **계약 변경은 다른 무엇과도 한 PR에 있지 않다.** 계약 경로와 그 밖의 소스가 한 PR에 섞이면 빨갛다.
- **구현한 에이전트가 아닌 리뷰 에이전트가 먼저 본다.** 보는 것은 셋 — 계약 위반, 태스크 범위 이탈, ADR과의 충돌. 지적과 답은 PR에 남고 사람은 남은 것만 본다. 반복되는 지적은 린트로 내린다.
- **에이전트는 승인을 기다리지 않는다.** 다음 태스크로 가고, 사람은 needs-human 과 하루 한 번의 요약만 본다. 잘못 들어간 것은 revert PR 하나로 되돌린다.

## 기각:
- **PR을 줄여 크게 묶기** — 사람이 읽지 못하는 크기가 되고, 한 부분의 잘못이 전체를 되돌린다(2026-09-08).
- **모든 PR에 사람 승인 유지** — 잦음을 견디지 못해 결국 묶게 된다. 위와 같은 길이다.
- **사람 승인을 아예 없애기** — 계약·결정·설정은 되돌리기 비싸고, 옳고 그름을 기계가 판정할 수 없다.
- **리뷰 에이전트 없이 CI만 믿기** — 린트와 테스트는 범위 이탈과 결정 충돌을 보지 못한다. 그것을 사람에게 남기면 승인 없는 PR도 결국 사람이 읽는다.

## 대가:
- **자동으로 들어가는 PR을 사람이 미리 보지 않는다.** 잘못이 main에 먼저 닿고 나서 revert된다.
- **리뷰 에이전트 한 번이 PR마다 든다.** 시간과 토큰이다.
- **자리 목록이 낡을 수 있다.** CODEOWNERS에 없는 새 자리는 자동으로 들어간다 — 되돌리기 비싼 자리가 생기면 먼저 거기 적어야 한다.

## 강제:
- **룰셋** `main` — PR 필수·강제 push 금지는 그대로, 승인은 코드 오너 리뷰 필수로. 필수 검사 이름은 `check` 하나(→ [ADR 0013](0013-stage-and-trigger.md)).
- **CODEOWNERS** `.github/CODEOWNERS` — 사람이 승인하는 자리의 정본.
- **파이프라인** `ops/pipeline/` — PR 크기 상한, 「결정한 것」과 needs-human 라벨의 대조, 계약 경로가 섞였는지.
- **리뷰** — 리뷰 에이전트가 계약 위반·범위 이탈·ADR 충돌을 본다. 사람은 코드 오너 자리와 needs-human 만.
- **워크플로** `.github/workflows/ci.yml` — 리뷰 에이전트와 하루 요약이 도는 자리.

## 상태:
승인됨 (2026-09-20). ADR 0003의 승인 강제(모든 PR에 승인 1개)를 코드 오너 자리로 좁힌다.
