# ADR 0017: 프로토콜 버전은 요청 헤더가 싣고, 미들웨어 한 곳이 판단한다

## 결정:
- 클라이언트는 모든 `/api/*` 요청에 `x-ade-protocol: <양의 정수>` 헤더를 싣는다. 값은 `contracts`의 `PROTOCOL_VERSION`.
- 서버는 미들웨어 한 곳(`core/protocol.ts`)에서 검사한다. 헤더가 없거나 지원하지 않는 값이면 **426 `VersionMismatch`**와 `supported: [...]`로 답한다.
- `/api/health`와 `/api/version`은 예외다 — 낡은 클라이언트도 자기가 낡았다는 사실을 알아야 한다. `/api/version`이 `protocolVersion`을 돌려준다.
- 클라이언트는 부팅 때 `/api/version`을 읽어 자기 버전과 다르면 "다시 불러오기"를 안내한다. Service Worker의 자동 갱신이 그 사이를 메운다.

## 기각:
- **요청 바디에 싣기([ADR 0015](0015-protocol-version.md))** — GET·DELETE·SSE에는 바디가 없다. 파일 목록·내용·감시가 전부 GET이라 정작 대부분의 요청이 버전 없이 나갔을 것이다. 0015가 "헤더는 zod 밖이라 검증이 두 갈래"라고 기각했는데, 헤더 검사는 미들웨어 한 곳이고 스키마는 손대지 않으므로 갈래가 늘지 않는다.
- URL 경로 버전(`/api/v1/`) — 0015와 같은 이유. 라우트가 갈라져 핸들러를 복제한다.
- 헤더 없는 요청을 허용하기 — 낡은 클라이언트를 잡으려는 장치인데 "없으면 통과"면 가장 낡은 클라이언트가 통과한다. `curl`로 부를 때는 헤더 하나를 더 붙이면 된다.
- 앱 레벨 인증 토큰(`Authorization: Bearer`) — 클라이언트에 그런 토큰을 `localStorage`에서 읽어 붙이는 코드가 남아 있었는데 발급하는 곳이 없다. 앱은 인증을 모른다([ADR 0014](0014-remote-access.md)). 지운다.

## 상태:
승인됨. [ADR 0015](0015-protocol-version.md)의 "요청 바디" 결정을 대체한다(버전을 둔다는 결정과 "서버가 판단한다"는 원칙은 그대로다). `ProtocolVersioned` 스키마는 지웠다.
