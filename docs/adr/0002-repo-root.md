# ADR 0002: 루트에는 전역인 것만 산다

## 맥락:
패키지가 셋이 되자 어느 패키지의 것도 아닌 파일이 루트에 쌓였다. 루트는 기본값이라 판단 없이 놓이고, 한번 놓이면 왜 거기 있는지 아무도 다시 묻지 않는다. 저장소 전체를 재검토하는 라운드에서 루트 항목의 절반이 실제로는 패키지 하나만 다스리고 있었다.

## 결정:
### 1. 루트에 놓이는 것은 패키지들이 공유하는 것이어야 한다.
- 그렇지 않은 것은 그것을 다스리는 패키지 안으로 다시 들여보낸다.
- **설정과 테스트도 예외가 아니다** — 다스리는 범위가 한 패키지면 그 패키지 안에 산다.

### 2. 루트에 놓이는 것도 의미 단위로 묶어 관리한다.
```text
<repo>/
├── .claude/                # Claude Code가 만드는 캐시
├── .output/                # 산출물 — 생성된 것은 전부 여기 모이고 추적하지 않는다
├── node_modules/           # 패키지 매니저가 만든다
├── docs/                   # 작업 기록, 구조적 결정
├── ops/                    # 운영 스크립트를 한 패키지로 모은다. 배포되지 않는다
├── packages/               # 실제 구현 코드 — 런타임에 돌고 이미지에 들어간다
├── tsconfig.json
├── pnpm-workspace.yaml
├── pnpm-lock.yaml
├── package.json
├── .gitignore
└── CLAUDE.md
```
- 항목을 늘리거나 줄이려면 **왜 전역인지를 한 문장으로 적고 승인을 받는다.** 그 문장을 쓸 수 없으면 전역이 아니다.

## 기각:
- 운영 스크립트를 `packages/` 아래 한 칸으로 두기 — `packages/`가 "배포되는 것"이라는 뜻을 잃는다.
- 빌드 산출물과 도구 생성물을 다른 폴더에 두기 — 성격이 같은데 규칙이 둘이 된다. 숨김 여부는 이유가 아니라 습관이다.
- 린트 설정 하나로 전 패키지 다스리기 — 절반이 한 패키지 전용이 된다. **글롭이 어긋나 죽어도 초록이라** 어디가 약해졌는지 좁힐 수 없다.
- 저장소 전역 테스트 폴더 — 두 패키지를 한 프로세스에 올려야만 성립한다고 믿었으나, 계약을 양쪽이 서로를 모른 채 각자 대면 그 필요가 사라진다.

## 강제:
- **리뷰** — 루트 항목의 추가·변경·삭제는 반드시 사용자의 승인을 받는다.
