# ADR 0006: 터널이 유일한 경로다 — 그래서 앱은 인증을 모른다

## 맥락:
ADE는 사용자 PC 한 대에서 돌고 바깥으로는 cloudflared Tunnel로만 열린다. **앱에는 인증이 없다** —
워크스페이스 파일 읽기·쓰기와 git 명령이 무인증으로 열려 있고, 그 워크스페이스가 사용자의 개인
디렉터리 전체다. 이 전제 위에서만 성립하는 배치가 있고, 그것을 코드가 이미 강제하는데 기록이 없었다.

## 결정:
- **호스트 포트를 하나도 열지 않는다.** cloudflared가 compose 네트워크 안에서 서비스명으로 직결하므로 터널이 앱으로 가는 **유일한** 경로다 — 그래야 "앱이 인증을 모른다"가 성립한다.
- **앱마다 전용 터널.** 공유 터널의 ingress 파일 하나를 여럿이 고치는 것보다, 컨테이너 하나(≈20MB)가 싸다.
- **Access가 문이다.** `accessEmails`가 비면 그 호스트는 무인증으로 열린다 — `up`이 경고하고, 배포 잡은 `anonSmoke`로 익명 요청이 막히는지 매번 확인한다.
- **DNS는 생성이 CLI(`cloudflared tunnel route dns`), 삭제만 REST다.** 그래서 `proxied`도 `<uuid>.cfargotunnel.com`도 우리가 알 필요가 없다.
- **`up`은 롤백하지 않는다.** 대신 되돌리기 어려운 단계에 닿기 전에 선다 — 자격증명 덮어쓰기 거부, DNS 자동 덮어쓰기 거부, 마운트 소스 확인, 유령 마운트 사전 검사.
- **미리보기는 실배포와 다른 파일이 정한다.** 개인 디렉터리를 마운트하지 않는 것을 파일 분리로 강제한다. 미리보기만 Access 앱까지 지운다 — 그 호스트 이름은 다시 쓰이지 않는다.
- **이미지가 커밋 SHA를 굽는다.** 더러운 트리면 `-dirty`가 붙는다 — 막지는 않되 남긴다.

## 기각:
- **Traefik 같은 공용 프록시** — 이 기계의 다섯 앱이 이미 앱마다 터널로 돈다. 프록시를 들이면 **공유 상태 사고**가 생기고, 얻는 것은 컨테이너 몇 개뿐이다.
- **와일드카드 DNS로 미리보기 열기** — 존이 Free 요금제라 **프록시된 와일드카드가 안 된다.** PR마다 레코드를 만들고 지우면 제약 자체가 사라진다.
- **배포 계약이 빌드도 맡기** — 둘을 묶으면 하나만 하고 싶을 때 길이 없다. `image`는 이미 만들어진 태그를 받는다.
- **실패 시 보상 트랜잭션** — 반쯤 지워진 상태가 아무것도 안 한 것보다 나쁘다.

## 대가:
- **터널이 안 뜨면 밖에서는 멀쩡해 보인다.** Access가 엣지에서 302를 주기 때문이다 — 그래서 `up`이 터널 컨테이너가 running이 될 때까지 기다린다(그 전에 성공을 보고한 적이 있다).
- **Access가 유일한 문이라 그것이 뚫리면 개인 디렉터리가 통째로 열린다.** 허용 이메일을 최소로 유지하는 것 말고 방어가 없다.
- 앱이 늘수록 터널·DNS·Access 앱이 1:1로 는다. Free 요금제의 한도는 아직 확인하지 않았다.

## 강제:
- **렌더러** `ops/deploy/render.ts` — `ports:`를 내지 않고, `name:`을 명시하고, 두 컨테이너에 `user:`를 붙인다. 셋 다 테스트가 지킨다.
- **`up`** `ops/deploy/up.ts` — DNS 다음에 곧바로 Access, 파괴적 단계 전 가드 넷.
- **배포 잡** `.github/workflows/ci.yml` — `needs`로 검사를 강제하고 `anonSmoke`로 끝낸다.
- **미리보기** `.github/workflows/preview.yml` — 포크 가드, 상한, 닫히면 `--purge --remove-access`.
- **청소** `ops/deploy/sweep.ts` — `pr-<숫자>`가 아닌 이름을 받으면 던진다.
