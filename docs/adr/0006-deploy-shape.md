# ADR 0006: 터널이 유일한 경로다 — 그래서 앱은 인증을 모른다

## 맥락:
ADE는 사용자 PC 한 대에서 돌고 바깥으로는 cloudflared Tunnel로만 열린다. **앱에는 인증이 없다** —
워크스페이스 파일 읽기·쓰기와 git 명령이 무인증으로 열려 있고, 그 워크스페이스가 사용자의 개인
디렉터리 전체다. 이 전제 위에서만 성립하는 배치가 있고, 그것을 코드가 이미 강제하는데 기록이 없었다.

## 결정:
- **호스트 포트를 하나도 열지 않는다.** cloudflared가 compose 네트워크 안에서 서비스명으로 직결하므로 터널이 앱으로 가는 **유일한** 경로다 — 그래야 "앱이 인증을 모른다"가 성립한다.
- **앱마다 전용 터널.** 공유 터널의 ingress 하나를 여럿이 고치는 것보다, 컨테이너 하나(≈20MB)가 싸다.
- **Access가 문이다.** 허용 이메일이 비면 그 호스트는 무인증으로 열린다 — 배포 잡이 `anonSmoke`로 익명 요청이 막히는지 **매번** 확인한다. 그것이 이 배포의 실질적인 자물쇠다.
- **터널 설정은 저장소 밖의 손으로 쓴 파일이 든다**(2026-09-13 개정). 터널 ID·호스트 이름·자격증명은 배포마다 바뀌지 않고, 저장소가 공개라 드러나서도 안 된다. `~/ARKA/secure/`의 파일 둘이 정본이고 compose는 **경로만** 값으로 받는다. DNS는 `cloudflared tunnel route dns`로 한 번 만든다.
- **배포는 `docker compose up -d`다**(2026-09-13 개정). 되돌리기는 이미지 태그를 `ade:previous`로 되돌려 같은 명령을 다시 돌리는 것이다. 예전의 `up`은 되돌릴 수 없는 단계(자격증명·DNS 덮어쓰기) 앞에서 서기 위해 가드 넷을 들었는데, 그 단계가 대시보드로 옮겨 가면서 가드도 함께 사라졌다.
- ~~미리보기는 실배포와 다른 파일이 정한다.~~ 2026-09-13 미리보기를 걷어냈다 — 관례에 없는 자체 인프라였다.
- **이미지가 커밋 SHA를 굽는다.** 더러운 트리면 `-dirty`가 붙는다 — 막지는 않되 남긴다.
- **파일 하나가 로컬·CI·실배포를 든다**(2026-09-13 개정). 실배포만 생성된 compose로 뜨면 **CI가 검사하는 것과 실제로 뜨는 것이 다른 파일**이 된다. 다른 것은 값뿐이고, 터널은 `--profile tunnel`로만 뜬다.

## 기각:
- **Traefik 같은 공용 프록시** — 이 기계의 다섯 앱이 이미 앱마다 터널로 돈다. 프록시를 들이면 **공유 상태 사고**가 생기고, 얻는 것은 컨테이너 몇 개뿐이다.
- **와일드카드 DNS로 미리보기 열기** — 존이 Free 요금제라 **프록시된 와일드카드가 안 된다.** PR마다 레코드를 만들고 지우면 제약 자체가 사라진다.
- **배포 계약이 빌드도 맡기** — 둘을 묶으면 하나만 하고 싶을 때 길이 없다. `image`는 이미 만들어진 태그를 받는다.
- **실패 시 보상 트랜잭션** — 반쯤 지워진 상태가 아무것도 안 한 것보다 나쁘다.
- **터널을 계속 코드가 관리하기**(2026-09-13) — 코드로 들면 Cloudflare REST·CLI 래퍼·락·manifest·유령 마운트 검사까지 약 2,500줄이 딸려 오는데, 그것이 다스리는 대상은 **한 번 만들면 바뀌지 않는 것 셋**(터널·DNS·Access)이었다.
- **원격 관리형 터널 + 커넥터 토큰**(2026-09-13) — Cloudflare가 요즘 미는 방식이고 compose가 env 한 줄로 끝나 더 단순하다. 고르지 않은 이유는 둘이다: 지금 도는 터널이 CLI로 만든 **로컬 관리형**이라 토큰으로 돌리면 원격 설정이 비어 전부 404가 되고, 이 기계의 API 토큰에 터널 권한이 없어 새로 만들려면 사람이 대시보드에 가야 한다. 파일 방식은 에이전트가 끝까지 할 수 있다.
- **compose 파일을 로컬용과 실배포용으로 가르기** — 갈리면 CI가 검사하는 것이 뜨는 것이 아니게 된다. 포트만 `compose.local.yml`로 뺐다 — 실배포에서 루프백 포트를 열면 docker 그룹이 없는 프로세스도 무인증으로 닿는다.

## 대가:
- **터널이 안 뜨면 밖에서는 멀쩡해 보인다.** Access가 엣지에서 302를 주기 때문이다 — 그래서 `up`이 터널 컨테이너가 running이 될 때까지 기다린다(그 전에 성공을 보고한 적이 있다).
- **Access가 유일한 문이라 그것이 뚫리면 개인 디렉터리가 통째로 열린다.** 허용 이메일을 최소로 유지하는 것 말고 방어가 없다.
- 앱이 늘수록 터널·DNS·Access 앱이 1:1로 는다. Free 요금제의 한도는 아직 확인하지 않았다.

## 강제:
- **compose** `ops/deploy/compose.yml` — 포트를 내지 않고, 프로젝트 이름을 명시하고, 앱을 호스트 uid로 돌리고, 터널을 `--profile tunnel` 뒤에 둔다. 이 파일이 CI의 `container` 잡이 검사하는 것과 같은 파일이다.
- **스모크** `ops/deploy/anonSmoke.ts` — 배포 잡의 마지막 단계. 익명 요청이 200을 받으면 실패다.
- **배포 잡** `.github/workflows/ci.yml` — `needs`로 검사를 강제하고 `anonSmoke`로 끝낸다.

## 상태:
승인됨 (2026-09-11). 2026-09-13 개정 — 배포 오케스트레이션을 걷고 compose 한 장으로 모았다. 터널 설정은 저장소 밖 파일이 든다.
