# ADR 0005: 병합 전 관문은 CI가 들고, `verify`는 손에 남는다

## 맥락:
안정적인 운영/DevOps를 위해서는 결국 CI가 필요하다.

## 결정:
- **병합 전 강제는 CI가 든다.** PR마다 `check`·`container`·`e2e`·`pr-title`·`secrets`가 돈다.
- **CI에만 있는 검사를 만들지 않는다.** CI는 로컬에서 부를 수 있는 명령만 부른다 — 그래야 빨간불을 재현할 수 있다.
- **`verify`는 손에 남는다.** 내보내기 전 한 번 도는 느린 관문이고, CI가 그것을 대체하지 않는다.
- **검사는 초록인 것만 켠다.** 지금 빨간 것(VRT)은 초록으로 만든 뒤에 넣는다. 빨간 관문은 무시하게 되고, 무시되는 관문은 없는 것만 못하다.
- **squash merge라 PR 제목이 곧 커밋 메시지다.** 그래서 커밋이 아니라 제목을 검사하고, 형식은 Conventional Commits + 한글 설명이다.
- **잡 이름은 계약이다.** 브랜치 보호의 필수 체크로 등록되므로 이후 바꾸지 않는다.

## 기각:
- **CI가 `verify`를 그대로 부르기** — 한 잡이 몇 분을 쥐고 어디서 깨졌는지 잡 이름으로 드러나지 않는다. 단계를 잡으로 갈라야 실패가 이름을 갖는다.
- **부분 검사(바뀐 패키지만)** — 전체가 20초라 아끼는 것이 10초 미만인데, 판단이 고장 나면 **조용히 덜 검사하면서 초록**이 된다. ADR 0001이 이미 재검토 기준을 적었다: 패키지 5개 이상 + CI 지연.
- **VRT·Docker 경계 스모크를 지금 넣기** — VRT는 기준 이미지가 낡아 빨갛고(TASK-35), 스모크는 `container` 잡과 겹치면서 느리다.
- **`pre-push` 훅으로 대신하기** — 훅은 `--no-verify`로 지나가고 남는 기록이 없다. 관문은 우회가 이력에 남는 자리에 있어야 한다(→ ADR 0003과 같은 이유).

## 대가:
- **설정이 저장소 안에서 두 벌이 된다** — `ops/pipeline/`과 `.github/workflows/`가 같은 명령을 부른다. 갈라지면 CI가 정본이다.
- **머지가 러너에 묶인다.** GitHub가 느리면 병합이 느리다.
- **`.github/`가 루트 항목을 하나 늘린다**(→ ADR 0002). 위치를 고를 수 없는 자리라 예외로 둔다.

## 강제:
- **워크플로** `.github/workflows/ci.yml` — 다섯 잡. 필수 체크 등록은 저장소 설정에서 사람이 한다.
- **commitlint** `ops/commitlint.config.ts` — PR 제목의 타입·scope·길이.
- **gitleaks** `ops/.gitleaksignore` — 새로 더해지는 커밋만 훑는다.
- **CODEOWNERS** `.github/CODEOWNERS` — 배치·설정·결정이 사는 자리에 리뷰가 자동으로 붙는다.
