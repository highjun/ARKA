# ADR 0003: `packages/*/src/` 밖은 사용자 승인 없이 건드리지 않는다

## 맥락:
사용자의 의도가 전혀 고려되지 않고, 검토 없이 여러 설정 파일들이 저장소 루트, 패키지 루트 등에 쌓이면서, 영향을 여러 곳에 미친다.
이로 인해 side-effect가 계속 발생하고, 사용자가 Repo를 리뷰하기 어려워졌다.
그에 따라, 어떤 변경이 일어날 때, 그 변경이 일어나는 자리를 정할 수 있는 명확한 규칙이 필요하다.

## 결정:
- **`packages/*/src/` 밖을 바꾸는 것은 구조 변경이다.** 사용자가 명시적으로 지정하지 않으면 건드리지 않는다.
- 예외적으로 임시 폴더는 상관 없다.(`.claude/`,`.output/`)

## 기각:
- 자유롭게 두고 리뷰에서 거르기 — 이번 세션에 `git add -A`가 **의도하지 않은 것을 세 번 쓸어담았다**(추적된 산출물 5.8MB, 사용자의 문서 삭제, 개인 메모). 리뷰가 diff를 다 읽지 못한다.
- 기본 차단 — 실측으로 **커밋 54개 중 밖을 안 건드린 것이 0개**다. 전건 위반인 규칙은 규칙이 아니라 백로그다. 막는 것이 아니라 **드러내는 것**이어야 한다.

## 대가:
밖을 고쳐야 하는 라운드마다 확인이 한 번 더 든다. 위 실측대로 그건 거의 모든 라운드다.

## 강제:
- **리뷰** — `제출 전 확인`의 한 줄 — 커밋 전 마지막으로 검토를 할 수 있도록 한다.
- **훅** `ops/hooks/preCommit.ts` — 밖의 변경을 커밋 때 변경을 메세지로 드러나게 한다.

## 상태:
